# 팀 배포 전 현황과 보충점

현재 판정: **같은 실험실 장비에서 사용하는 내부 시험용 베타**. 팀원별 새 Windows PC 설치와 새 S-curve 중간 강도 실차 검증은 아직 완료되지 않았습니다.

## 배포 전 우선순위

### 1. 실제 길이와 검출 정확도 검증

현재 최대 상승은 **영상 평면 px**입니다. mm를 표시하려면 컵과 같은 깊이 평면에 자/기준 마커를 두고, 렌즈 왜곡·시점·기울기를 보정해야 합니다. 컵 뒤 보드의 격자만으로 물리 mm 정확도를 보장하지 않습니다. 수동으로 액면을 표시한 검증 프레임과 OpenCV 결과의 높이 오차·최대 순간 시간 오차를 비교해 허용 오차를 정해야 합니다. 젖은 컵 벽·반사·뚜껑 가림·움직임 흐림·컵 배율 변화도 포함하세요.

### 2. 실제 IMU/트레이 데이터 연결

현재 실제 IMU가 없는 촬영은 빈 CSV/미수신으로 남깁니다. 차체 IMU와 트레이 ESP32 Roll/Pitch를 구분하고, 각 센서의 원시 timestamp·단위·샘플률·축 방향·유효율·교정 정보를 저장해야 합니다. LiDAR CP2102 포트를 ESP32로 오인하지 않아야 합니다. 서보 명령각과 실제 측정각도 별도입니다. 트레이 LEVEL/PREDICTIVE는 연결·응답·실차 검증 전 자동 활성화하지 않습니다.

### 3. 반복 실험과 조건 비교

같은 용기·물 질량/수위·속도·S 강도·가속도/Jerk·트레이 조건을 3회 이상 반복하세요. 측정값 평균·표준편차·실패율·유효 검출률·실제 정지거리 편차로 비교해야 합니다. S 강도가 다른 시험을 같은 그룹에 합치지 않습니다. 순서를 섞고 배터리·모터 온도/부하·바닥 상태 변화도 기록하세요. 현재 다음 시험 추천은 검증된 반복 자료가 부족하면 제한되며, 자동 최적화 성능이 입증된 상태가 아닙니다.

### 4. 배포 설치·장치 진단

새 노트북에서 Python/의존성/카메라 권한/코덱/SSH 초기 설정/ROS 도메인/직렬 장치 식별/저장 여유를 점검하는 설치 수용시험이 필요합니다. 개인 SSH 키·암호·토큰·OAuth 인증 파일은 팀 배포 ZIP에 포함하지 않습니다. 각 팀원이 자기 연결 인증을 해야 합니다. Jetson IP가 바뀌는 경우를 대비해 고정 주소 또는 장비 선택 절차가 필요합니다. 재부팅 후 연결, USB 재연결, 네트워크 지연, 디스크 부족, 업로드 실패 보존, 중단 후 복구를 새 PC에서도 확인하세요.

## 실험마다 더 남길 데이터

- 용기 ID·내경·형상·실제 액체 질량/정지 수위·뚜껑 유무, 물감/용액 배합과 온도. 현재 입력 기본값을 실제 측정값처럼 사용하지 마세요.
- C920 노출·셔터·초점·화이트밸런스·설치 위치·해상도·실측 FPS·프레임 간격/누락·동기화 불확실성. 밝기를 고정하고 빠른 출렁임의 모션 블러를 확인하세요.
- 실제 속도·가속도·제동 명령 시각·완전 정지 시각·초과거리·정속 구간·최대 상승 시각·안정화 판정과 미확인 사유.
- 센서/검출/연구 프로토콜의 유효 여부, 성공·중단 사유, 코드 버전·교정 버전·분석 파라미터. 없거나 측정하지 않은 값은 빈값과 사유를 저장하세요.

## S-curve 강도 정의

이 프로그램의 비교 척도이며 표준화된 물리 백분율이 아닙니다. 100에서 기존 설정 Jerk를 적용하며, 0보다 큰 강도 p에서 **적용 Jerk = 설정 Jerk × 100 / p**입니다. 가속도·목표 속도 상한은 유지됩니다. 0은 가속도가 갑자기 바뀌는 기존 사다리꼴 속도 프로파일입니다. 숫자가 커질수록 가속도 변화가 완만해집니다. 거리 급정지 시 영속도 명령과 안전정지는 이 필터를 우회합니다. 급정지까지 부드럽게 만들면 서로 다른 시험이 되므로 현재 실험에서는 변경하지 않습니다.

## 검증 범위 구분

주행·영상 저장 성공은 연구 프로토콜 합격과 다릅니다. C920의 1080p·미수신 IMU·불확실한 시각 동기화는 해당 조건을 요구하는 연구 기준을 충족하지 못합니다. 개인 장비에서 한두 번 성공한 속도를 팀 전체의 검증 완료 범위로 자동 등록하지 않습니다. 장애물 자동정지가 꺼진 직선 실험 설정도 팀원에게 명확히 전달해야 합니다.
