## 기본 버튼 동작

03 패널의 **수평 유지 확인 후 L자 시험 시작**을 누르면 다음 순서로 동작한다.

1. 차체 정지·센서 상태와 ESP32의 두 서보 활성화·IMU·영점·방향 확인을 검사한다.
2. 필요한 경우 `h`로 수평 유지를 요청한다. 서보 켜기, 영점 저장, 방향 확인은 자동 수행하지 않는다.
3. 트레이가 기준에서 ±10°를 넘으면 시작을 거절한다. 실제 MODE=4와 두 축 ±1° 이내 상태를 0.25초 확인한 뒤 출발한다. 4초 안에 준비되지 않으면 출발하지 않는다.
4. 첫 직선 3.2m, 절반 1.6m에서 급정지, 정지 피드백 1초 확인, 첫 직선 나머지 이동.
5. 정지 확인 후 우회전 90°, 두 번째 직선 2.2m, 도착 정지 확인.

거리·중간 급정지 선택은 변경 가능. 기본 속도 12cm/s, L자 시험 상한 20cm/s.
짧은 검증은 기존 60cm/10초 한계를 유지하며 중간 급정지를 추가하지 않는다.
수평 유지 모드는 기존 PROTO=1에서도 가능하지만, 예측 목표 추종은 PROTO=2 펌웨어가 필요하다.

## 안 끊기게 한 범위

- 경로·모터 명령·센서 검사는 Jetson 내부의 단일 차체 USB 소유 프로세스가 담당한다.
- Windows/Wi-Fi가 트레이 목표를 중계하지 않는다.
- L자 자동 주행 중 창 전환/페이지 이탈만으로 정지 요청을 보내던 부분을 분리했다. Windows 화면이 끊겨도 로컬 센서가 정상이라면 주행이 계속될 수 있다.
- 명시적 정지 버튼·Space/Esc·Windows 연결 창의 접속 종료는 정지 요청을 보낸다. 네트워크 단절 시 원격 정지 전달도 지연될 수 있다.
- 수동 조종의 입력 만료·창 이탈 정지는 그대로 유지한다.
- 장애물·실제 차체/ESP32 통신 단절·오래된 센서·진행 없음은 계속 검사한다. 깊이 일시 지연은 정지 후 새 영상으로 복구하며 3초 내 복구되지 않으면 종료한다.

무조건 완주를 보장하거나 실제 센서가 끊겨도 강제 주행하는 변경은 아니다. 깊이 유효 영역 부족과 차체/USB 전원 문제 자체를 해결한 것으로 간주하지 않는다.

## 선택 기능: 예정된 급정지 선행 기울이기

03 패널의 **ESP32 연동 · 급정지 선행 보정 + 수평 유지**를 체크한다. 기본 선행 시간 200ms, 각도 제한 2°. 허용 범위는 50~500ms, 0.5~3°다.
선행 보정 축/부호는 기존 주행·트레이 제어실의 예측 설정을 따른다. 실제 장착 방향에 맞게 먼저 무주행 시험해야 한다.

```text
Jetson 경로 엔진
  → 남은 거리 / 실제 보고 속도로 정지 예정 시간 계산
  → 설정한 제동시간 모델(기본 0.20초)로 목표각 계산
  → /d420/tray/route_target (20Hz, depth=1, best-effort)
  → 기존 tray_monitor 단일 USB 소유자
  → @T,roll,pitch + 줄바꿈
  → ESP32의 트레이 IMU 피드백 / MODE=7 또는 앱용 MODE=5
```

출발 전에는 0° 목표로 소유권을 획득하고 실제 펌웨어가 예측 모드를 보고하는지 확인한다. 1.5초 안에 확인되지 않으면 차체는 출발하지 않는다.
300ms 목표 수신 만료는 로컬 모니터에서 수평 복귀를 요청한다. 기존 펌웨어의 500ms 목표 만료도 유지한다.
경로/순번/시각을 검사하고 오래된 목표·역순·종료된 경로 재전송을 거부한다. UI와 경로가 동시에 목표를 전송하지 않는다.
운영자의 수동 트레이 명령은 경로 소유권을 해제하며, 주행 중 해제되면 차체가 정지한다.

일반 주행 및 오르막의 기본 목표는 트레이의 실제 수평 0°다. 차체 경사각을 임의로 한 번 더 더하지 않는다.
현재 예측은 주행 계획과 오도메트리 속도 기반 모델이다. 실측 차량 가속도/차체 Pitch/Roll이나 깊이 영상 지형 예측을 사용하지 않는다.
차체 IMU가 없어도 트레이 IMU로 수평 유지와 계획 기반 능동 보정은 가능하다. 가감속 중 BNO055 자세 추정 오차, 실제 제동시간, 서보 응답과 액체 출렁임은 별도 실측이 필요하다.

## d420_core.py 확인 결과

Drive의 `01_D420_전체소스코드.zip`에 있던 `external/d420_ros_integrated/d420_core.py` 백업본을 확인했다.

- `function == 5`, `length == 10` 패킷에서 `pkt[9:12]`의 부호·각도를 yaw로 읽는다.
- yaw는 최초 방향 대비 부호를 보정한 라디안 값이다.
- `function == 2`는 vx/vy/wz 보고 속도다. 이것을 원시 가속도/자이로 데이터라고 부르지 않는다.
- 현재 Decoder는 Roll/Pitch/가속도 필드를 노출하지 않는다. 차체가 그 값을 보내지 않는다는 증거는 아니다.
- 실제 Jetson의 현재 파일/통신규약/원시 수신 데이터는 아직 대조하지 못했다. d420_core.py는 변경·배포하지 않았다.

Jetson 검색 명령:

```bash
find ~/d420_ws ~/d420_ros_integrated -type f -name d420_core.py 2>/dev/null
```

참고용 core와 serial_bridge 백업은 Windows 패키지의 reference 폴더에 있다. 현재 Jetson 파일 대신 덮어쓰지 않는다.

## 적용 순서

1. 로봇을 정지하고 기존 Windows 연결 창을 닫는다.
2. 이번 ZIP을 새 폴더에 전체 압축 해제한다.
3. `Setup-Jetson.cmd`로 기존 앱을 백업하고 Jetson 서버를 업데이트한다. 사용 중인 tray-monitor는 구버전일 수 있으므로 업데이트 후 앱에서 ESP32 연결을 다시 시작한다.
4. `Install-HongikCafe.cmd`로 Windows 바로가기를 업데이트한다.
5. ESP32 USB 데이터 연결, 서보 정격 전원·공통 GND를 확인한다. 서보 전원은 Jetson USB가 공급한다고 가정하지 않는다.
6. 실제 수평 영점과 축 방향을 확인한다. 기본 수평 + 짧은 직진부터 확인한다.
7. 예정 급정지 예측을 쓰려면 해당 보드용 PROTO=2 펌웨어가 필요하다. 포함된 `esp32_level_predictive_v4.ino`는 ESP32-S3 GPIO18/17, SDA8/SCL9 설정이다. 다른 ESP32 보드/배선에 그대로 올리지 않는다. 원본 백업·NVS·부트로더·파티션을 보존해야 한다.
8. 무주행 작은 목표각 시험 후에만 예측 체크를 켜고 L자 시험을 진행한다.

## 검증과 미완료

- 제어·모의 USB·HTTP API 시험 27개: 전체 L자, 실제 급정지 전 음의 예측 목표 전송, 수평 복귀, 원본 프로토콜 수평 모드, 준비 중 정지 취소, 원본 펌웨어 예측 차단, USB/IMU 손실 정지, 목표 만료/역순 거부 등을 확인한다.
- Edge 로컬 HTTP fixture 시험 1개: 수평 연동/예측 옵션 전달, L자 중 창 전환·네트워크 단절 시 불필요한 STOP 없음, 명시적 STOP, 수동 창 이탈 정지 확인.
- ESP32-S3 `esp32:esp32:esp32s3:CDCOnBoot=cdc`, Arduino ESP32 3.3.12로 기존 예측 펌웨어 컴파일 통과. 프로그램 380281/1310720B, RAM 24328/327680B. 일반 보드 설정의 컴파일이며 현재 실물 플래시 배치에 맞는 자동 업로드를 뜻하지 않는다.
- 현재 Jetson 192.168.0.47:22에는 연결되지 않았다. 실물 배포·주행·오르막·물 유출량/제동거리 검증은 미완료다.
