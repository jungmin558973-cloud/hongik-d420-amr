# HONGIK CAFÉ 사람 따라가기 — 2026-11-07 현재 설정

## 사용

1. Jetson과 배터리 차체 전원을 켜고 ASUS와 같은 K221 네트워크에 연결한다. Jetson은 `seo@192.168.0.47`, SSH 별칭은 `hongik-jetson`이다.
2. ASUS에서 `bash ~/d420_ws/scenario_lab/open.sh --follow`로 큰 카메라 화면을 연다.
3. 연결이 없다면 **실차 연결 준비**, 검출기가 없다면 **사람 검출 준비**를 누른다. 이 버튼들은 추종을 시작하지 않는다.
4. 처음에는 카메라 앞 0.5~1m에 한 사람만 서서 박스와 실제 거리값을 확인한다.
5. **유지 거리 0.3m → 이 사람 따라가기 시작**. 멀어지면 전진하고 가까워지면 직선 후진한다. 목표 부근에서 멈춰도 세션을 유지하며 사람이 움직이면 다시 반응한다.
6. **추종 정지 / Space / Esc**로 종료한다. 브라우저 창 전환·연결 단절도 종료한다. 사용자 정지 이후에는 시작 버튼을 다시 눌러야 한다.

거리값은 **카메라에서 검출된 신체 영역까지의 깊이**다. 바퀴·차체 끝에서 사람 발끝까지의 거리가 아니며, 절대 30cm 정지 정확도를 보정하거나 보증한 것은 아니다. 앞뒤 여유 공간과 실제 깊이가 확인될 때만 이동한다.

## 거리 유지와 속도

- 설정 범위 0.3~2m, 기본 0.3m, 정지 여유 ±0.02m. 오차에 비례해 가감속하며 목표 가까이에서 감속한다.
- 전진 최대 0.12m/s, 후진 최대 0.06m/s, 회전 최대 0.30rad/s. 수동 주행의 0.30m/s 한도와 별개다.
- 관측 거리 0.55m 미만의 전진은 최대 0.06m/s, 0.40m 미만은 최대 0.025m/s다.
- 전진 가속도 0.25m/s², 후진 가속도 0.15m/s². 전후진을 전환할 때 먼저 0속도를 보내고 차체 속도 절댓값이 0.025m/s 이하인지 확인한다.
- 후진 중에는 회전 명령을 보내지 않는다. 차체 회전 중에도 정지한 뒤 후진한다. 사람을 화면 중심으로 맞추는 전진·제자리 회전은 유지한다.
- 깊이 0.20m 미만 또는 구멍·동기화 문제로 거리 확인이 안 되면 멈춘다. 없는 깊이를 추정하거나 이전 거리로 후진하지 않는다.
- 후진은 후방 3개 구역 모두 충분한 최신 라이다 관측이 있어야 한다. CAD 차체 범위, 10cm 여유, 속도에 따른 제동 여유와 0.6초 이동 궤적을 확인한다. 전진·회전도 같은 근접 공간 검사를 적용한다.
- 높은 속도에서만 여유가 부족하면 같은 라이다 검사에서 통과한 낮은 속도로 줄여 계속 이동한다. 감속→가속→완전 정지를 반복하는 현상을 줄인다. 낮은 속도에서도 공간이 부족하면 세션을 종료하지 않고 0속도로 대기한다. 여유 공간이 생기면 같은 대상 관측을 이용해 다시 반응한다. 장애물을 우회하는 경로 계획은 없다.
- 이전 사용자 요청에 따른 수동·시나리오 장애물 자동 정지 해제 설정은 그대로다. 근접·후진 공간 검사는 사람 추종에만 추가했다.

## 검출과 다시 움직이는 조건

YOLO11n COCO person + D435 정렬 깊이를 사용한다. TensorRT FP16 416×416 모델은 Jetson에서 실행한다. 검출 타이머는 20Hz, 센서 스택의 독립 `camera_relay.py`가 JPEG를 최대 10Hz 전송하며 실제 처리·전송률은 부하에 따라 달라진다.

- 처음 선택은 한 사람만 보이고 0.4초 이상 안정적으로 검출됐을 때 가능하다.
- 잠깐 놓치거나 깊이가 불확실하면 즉시 0속도로 기다린다. 같은 대상의 최신 관측을 0.15초 이상, 서로 다른 촬영 시각 3프레임 이상 확인하고 재개한다.
- 시각적 ID는 최대 2초 동안만 보존한다. 누락 뒤 복귀는 이전 박스와의 IoU>=0.25 및 색 히스토그램 거리<=0.25를 확인하고 0.2초 안정화한다. 얼굴 인식이나 장시간 재식별은 아니다.
- 이미 선택한 사람이 계속 식별되면 배경의 추가 검출만으로 세션을 끝내지 않는다. 대상 선택이 모호하면 멈춰 재확인한다.
- 낮은 카메라에서 가까운 한 사람의 두 다리가 각각 사람으로 검출될 때: 기존 대상 박스와의 연속성, 위쪽 잘림과 기하 관계, 양쪽 색 유사성, 양쪽 **실측 깊이 차 0.12m 이하**를 모두 확인한 경우만 같은 대상으로 묶는다. 다리 사이 배경 깊이는 쓰지 않는다.
- 두 사람을 정확한 신원으로 구별하는 기능은 아니다. 모호한 장면에서는 정지하거나 재선택이 필요하다. 처음부터 두 명을 하나로 선택하지 않는다.
- 관측 누락 3초 이상, 다른 ID, 검출 발행자 중복, 잘못된 수치/시각, 오도메트리 이상, 브라우저 heartbeat 단절, 제어 지연은 종료한다. 이 경우 다시 시작해야 한다.

깊이는 신체 박스 안의 3×3 영역에서 측정한다. 유효 픽셀 30% 이상·최소 32픽셀인 영역 중 중앙 열을 포함하는 인접 영역의 깊이가 일치해야 한다. 고립된 픽셀, 측면 배경만 있는 장면, 서로 다른 깊이는 거절한다. 앱의 민트색 영역이 실제 사용한 깊이 영역이다.

D435 자료의 848×480 깊이 모드 Min-Z는 195mm다. 이는 실내 모든 신체·표면에서 0.3m 깊이가 유효하다는 뜻은 아니다. 실제 유효 깊이가 없을 때는 계속 정지한다.

## 구성과 앞뒤 방향

`D435 RGB + aligned_depth_to_color → Jetson person_detector.py → /d420/follow/observation JSON → ASUS 홍익 카페 Follow → /d420/manual_cmd_vel → USB 차체 브리지`

검출기는 모터 명령을 발행하거나 시리얼 포트를 열지 않는다. 수동·시나리오·추종이 기존 앱의 한 속도 발행자를 교대로 사용한다. 부팅·앱 열기·검출기 시작만으로 주행하지 않는다.

- Jetson Orin Nano 8GB, Ubuntu 22.04, ROS Humble, JetPack R36.4.7.
- ROS_DOMAIN_ID=120, ROS_LOCALHOST_ONLY=0, rmw_fastrtps_cpp.
- CH340: `/dev/serial/by-id/usb-1a86_USB_Serial-if00-port0`.
- RealSense D435 USB3. RGB 640×480×30, depth 848×480×30, enable_sync와 align_depth 활성화, frames_queue_size 1.
- ASUS 앱 `http://127.0.0.1:8765/?drive=follow&mode=real&camera=full`.
- 사용자가 W/↑ 전진은 카메라 쪽이라고 확인했다. 이 명령 부호를 유지한다. raw odom v 부호의 전체 보정은 하지 않았으므로 방향 전환에서는 속도 절댓값으로 정지를 확인한다. yaw 실제 방향 검증은 별개다.
- 트레이는 실행 안함 또는 IMU 수평 유지. 추종 중 트레이 예측 보정은 지원하지 않는다.

## 영상 전송에서 유지해야 하는 설정

기본 `/camera/camera/color/image_raw/compressed` 발행자가 없었다. ASUS가 원본 RGB를 WiFi로 받으면 약 0.4초 지연과 깊이 단절이 생겼고 원본 구독을 닫으면 정상화됐다. 현재 센서 스택의 독립 `camera_relay.py`가 `/d420/follow/camera/compressed`에 JPEG quality70을 발행한다. 앱의 원본 RGB fallback은 제거했다. YOLO 시작·재준비·중지와 관계없이 카메라 전송은 유지된다. 진단을 위해 ASUS에 원본 RGB·깊이 구독을 추가하지 않는다.

RealSense `rs_launch.py`의 config_file은 평평한 파라미터 사전이다. `/**/ros__parameters` 등으로 감싸지 말고 `jetson/camera.yaml` 형식을 유지한다. 적외선 emitter_enabled=1, laser_power=150을 확인했으며 임의로 올리지 않았다.

큰 카메라 화면은 전체 640×480 영상을 `object-fit:contain`으로 표시하고 창 높이에 맞춘다. 기본 3D 화면으로 돌아가는 버튼도 있다.

### 적용 후 읽기 전용 실측과 현재 미해결 항목

검출기 재준비 후 6초 측정에서 관측 108개 전부 ready=true, 누락 RGB 0개, 관측 약 19.2Hz, source age 중앙값 0.112초·최대 0.137초, 추론 중앙값 23.0ms였다. 속도 발행자는 앱 하나만 있었다.

사용자가 앱에서 실행한 12:26 세션은 21.3초 동안 샘플 419개, 명령 최대 전진 약 0.077m/s·회전 약 -0.184rad/s를 기록했으나 차체 속도 피드백은 0이었다. 사용자가 실제로 움직이지 않았다고 확인했다. USB 로그에는 13바이트 이동 패킷 쓰기 성공, live=True/cmd_live=True, 수신 체크섬 오류 0이 기록됐다. 현재 브리지 소스 해시는 이전 설정과 동일하다. OS의 쓰기 성공이 차체 MCU의 명령 수락을 증명하지는 않는다. 차체 전원·리모컨 모드 우선권 등은 별도 확인 중이며, 주행 복구 완료로 기록하지 않는다.

12:30경 추가 진단에서 0.025~0.08m/s는 공간 검사를 통과하고 0.10~0.12m/s는 근처 물체 때문에 거절됐다. 이전의 이진 정지 방식은 명령이 올라갈 때마다 0으로 초기화해 최대 0.31초짜리 이동 명령을 반복했다. 현재는 원래 명령이 거절되면 75%→50%→25% 속도에서 동일한 공간 검사를 다시 하고, 통과한 속도만 사용한다. 실제 관측 누락이나 낮은 속도에서도 막힌 공간은 계속 정지한다. 실제 발행 속도와 차단·감속 사유는 JSON·CSV에 기록한다. 차체 켜짐·리모컨 꺼짐은 사용자가 확인했으나 MCU의 명령 수락 상태는 아직 미확인이다.

### 12:38 실차 추종 반응 확인

사용자가 "이제 따라 오긴 한다"고 실제 이동을 확인했다. 해당 세션은 약 34.95초, 최대 명령 전진 0.0869m/s, 최대 차체 보고 속도 절댓값 0.112m/s, 누적 odom 이동 약 0.734m였다. 따라서 앞선 12:26 무반응 상태와 구분한다. 후진 명령은 이 세션에 없으므로 실제 역방향 거리 유지 시험 완료는 아니다. 사용자 정지로 종료했다.

끊김 분석: 689개 샘플 중 follow_wait 154개(약 7.7초), 공간 부족 hold 123개(약 6.2초)였다. 여유 공간에 맞춘 감속은 159개 샘플에 기록됐다. 정지 원인을 기록하고 실제 거리 수신을 안정화하는 것이 우선이며, 센서 확인 없이 이동을 유지하도록 바꾸지는 않는다.

### Jetson 전원선 이탈 후 재연결과 영상 수신 안정화

사용자가 Jetson 전원선 이탈·재연결을 알렸다. 부팅 초기 시계가 저장 시각 12:05로 복원됐다가 NTP로 12:40에 동기화됐고, by-id USB 이름은 유지되지만 ttyUSB0/1 번호는 서로 바뀌었다. 영구 읽기 전용 hongik-robot만 자동 시작했고 임시 모션·검출기 서비스는 꺼져 있었다. 앱은 odom 초기화를 감지해 준비 불가 상태였다.

재연결에서 발견한 두 문제를 보완했다.

1. 연결 준비 응답이 카메라 노드 발견보다 먼저 반환돼 검출 준비가 Node not found로 실패했다. follow_session.sh는 카메라 파라미터 서비스가 나타날 때까지 최대 20초 기다린다.
2. 검출기 시작 전 원본 RGB fallback이 다시 WiFi 구독을 만들었고 D435에 Out of frame resources 오류가 발생했다. 카메라 JPEG 전송을 센서 스택의 독립 노드로 분리하고 앱 원본 fallback을 제거했다. 검출기 재시작으로 영상 전송이 같이 끊기지 않는다.

중복된 홍익 카페 전용 창 8개와 검증용 headless 창은 정지 상태에서 정리하고, 실차·0.3m·전체 카메라 조종 창 하나를 열었다. 정상 검출 중 준비 버튼은 "검출기 실행 중"으로 표시해 반복 준비 대신 아래 추종 시작 버튼을 사용하게 했다.

복구 후 최종 읽기 전용 검증: JPEG 발행자 1개, 원본 RGB 구독자는 Jetson의 hongik_person_detector와 hongik_camera_relay 두 개뿐이며 ASUS 원본 구독은 없었다. 약 6초에 JPEG 58프레임, 관측 99개, 관측 중앙 주기 약 19.7Hz, 원본 촬영 시각 기준 지연 중앙값 0.086초·최대 0.352초였다. 당시 사람은 화면에 없어 추종 ready=false였으나 카메라 640×480과 실차 센서는 ready=true였다. 최신 실제 조종 창에서 0.3m, 검출기 실행 중, 시작 대기 상태를 확인했다. 복구 검증 중 이동 명령은 생성하지 않았다. 이번 영상 전송 분리 후의 부드러운 실차 추종과 근접 후진은 추가 현장 확인이 필요하다.
