# 배포 08 · 15조건 L자 실험

`2026-11-16-08-15-CASES`. 이 문서가 최신 적용 기준이다. 소프트웨어 구현·모의 검증이며 실물 Jetson 설치와 20/30/40cm/s 주행 검증은 아직 수행하지 않았다.

## 회전 위치

회전 전 추가 직진 기본값을 **30cm**로 추가했다. 첫 직선 3.2m이면 **3.5m 직진 후 우회전 90°**, 두 번째 직선 2.2m다. 기존 첫 직선 절반 1.6m의 중간 정지 위치는 변경하지 않는다. 설정한 첫 직선이 다르면 그 값에 30cm를 더한다. 실제 설치 위치·주행거리·차체 제동 오차에 따라 바닥 표시와 실측 대조가 필요하다.

## 실험 버튼

지도·지점 이동 화면의 **03 L자 비교 실험 · 15조건**에 아래 버튼 표가 있다. 각 칸을 누르면 해당 조건으로 한 번 실행한다. 실험 회차도 입력할 수 있다. 모든 조건은 같은 경로·회전·중간 정지 목표를 사용한다. 시험 후 자동으로 출발점까지 돌아오거나 15회를 연속 실행하지 않는다. 다음 실험 전 같은 출발 위치·방향으로 로봇을 놓는다.

| 조건 | 20cm/s | 30cm/s | 40cm/s |
| --- | --- | --- | --- |
| 무보정 · PWM 고정 | baseline | baseline | baseline |
| 수평 유지 | level | level | level |
| 능동 트레이 + 수평 유지 | active | active | active |
| S-curve 감속 · 트레이 무보정 | scurve | scurve | scurve |
| 능동 트레이 + S-curve | combined | combined | combined |

- 무보정은 서보를 해제하는 조건이 아니라 **저장한 수평 영점 홈 PWM으로 복귀해 고정**하는 조건이다. 자유 관절과는 다르다. 차체가 기울면 트레이도 차체를 따른다. 시작 전에 MODE=0·홈 PWM을 실제 보고로 확인한다.
- 수평 유지는 기존 트레이 IMU 기반 MODE=4다. 영점 ±1° 상태를 확인한 뒤 출발한다.
- 능동 트레이는 수평 유지에 주행 명령·중간 제동 계획의 목표각을 더한다. 차체 Roll/Pitch/선형 가속도 IMU 실측은 현재 사용하지 않는다. PROTO=2 예측 펌웨어와 실제 축/부호 확인이 필요하다.
- S-curve는 **차체의 계획된 감속**에 적용한다. 중간 정지, 회전 전 정지, 도착 정지에서 5차 다항식 속도 프로파일을 사용한다. 계획 프로파일의 최대 감속 0.25m/s², jerk 0.6m/s³를 기준으로 시간을 계산한다. 실물 바퀴/하중의 감속·jerk를 보장하는 수치는 아니다.
- 능동+S-curve는 향후 계획 가속도와 현재 속도·각속도 모델로 트레이를 선행 보정한다. 기본 트레이 예측각 한계 ±2°, 허용 설정 최대 ±3°다. 실제 최적 각도·선행 시간은 실험으로 조정한다.
- 비교 조건은 중간 정지를 항상 포함하며, 중간·도착 정지 후 2초간 상태를 기록한다. 보정 없음/수평/능동 조건의 중간 정지는 기존의 즉시 0 명령이다. 시작 가속은 기존 제한을 사용하고 S-curve 비교는 계획 감속 부분이다.

## 장애물·경로 복귀·연결

사람이나 장애물이 들어오면 S-curve보다 충돌 정지가 우선한다. 큰 속도에서 낮은 후보 명령만 보고 여유 공간을 과소평가하지 않도록 실제 보고 속도까지 사용해 기존 전방 궤적을 검사한다. 제동 성능이 확인되지 않은 40cm/s로 바로 시험을 시작하지 않는다.

중간 정지나 사람 통과 대기 후에도 원래 출발 기준 좌표·구간 목표를 유지한다. S-curve 중 멈췄다면 현재 위치·속도로 감속을 다시 계획한다. 작은 방향 보정 뒤에는 원래 직선 방향과 횡방향 오차를 줄이며 복귀한다. 10cm 횡방향 오차를 넣은 모의시험에서 회전 지점 오차가 5cm 안으로 줄어드는 것을 확인했다.

이는 지도를 이용해 큰 장애물을 한 바퀴 돌아가는 완전한 우회 계획이 아니다. 전방 카메라만으로 측후방 빈 공간을 보장할 수 없어 **25cm 이상 횡방향 이탈, 장애물 장기 대기, 센서/모터/ESP32 실패는 정지**한다. 큰 우회·전역 재계획에는 검증된 지도·로봇 위치·전후방 관측을 사용하는 Nav2 경로 계층이 별도로 필요하다.

한 번 수락된 L자 실행과 기록은 Jetson 내부에서 진행한다. Windows 화면 전환·닫기, Wi-Fi 끊김, 웹 서버 재시작만으로 취소하지 않는다. 모터·센서·로컬 제어 프로세스는 계속 동작해야 한다. STOP/Space/Esc와 Windows 연결 창의 명시적 접속 종료는 정지 요청을 보낸다. 연결이 끊기면 원격 정지 요청도 전달되지 않을 수 있으므로 현장 정지 수단이 필요하다. 절대 끊기지 않거나 반드시 완주한다는 보장은 하지 않는다.

## 센서와 데이터

모든 15조건에서 ESP32를 연결해 같은 센서로 비교한다. 연결되지 않으면 비교 버튼이 비활성화되며 서버도 시작을 거부한다. 보정 없음도 각도 기록과 PWM 고정 확인이 필요하다. 현재 확인한 실차 앱에서는 차체/깊이는 연결됐지만 ESP32 상태가 수신되지 않았고, 배포 07의 DB/수평 연동 전 버전이었다. 이는 확인 당시 상태이며 USB 미삽입을 단정한 것은 아니다.

`runs/experiments.sqlite3`에 실험마다 조건 ID, 목표 속도, 반복 회차, 경로·추가 직진, 배포 버전, 트레이 설정과 실제 값을 누적한다. 실험 기록 화면에서 조건·속도·회차, 결과·정지 사유, 관측 최대 Roll/Pitch와 샘플 수를 보고 CSV/JSON을 내려받는다.

주요 신호는 Unix/monotonic 시각, x/y/yaw, 명령·실제 보고 속도/각속도, 속도 차분 가감속, 명령 jerk, 트레이 측정각/요청 목표각/ESP32 보고 목표각, PWM·영점·모드·프레임 수, 깊이 지연, 예측 모델·ETA, 정지 단계·사유다. 장애물 정지와 S-curve 재계획 이벤트도 기록하므로 외부 개입이 있는 시험을 구분할 수 있다.

종료 시 관측 최대 각도·Roll/Pitch RMS·최대 보고 속도·최소 계산 가속도·최대 명령 jerk·새 ESP32 프레임 수를 요약한다. 미리보기 값과 실차 값은 모드로 구분한다. DB 스키마 추가는 기존 테이블을 보존하는 방식으로 적용한다.

**20Hz 제어 기록과 ESP32 실측 주기는 다르다.** 현재 펌웨어의 전체 상태 보고는 통상 약 2Hz다. 반복 프레임에는 새 센서값이 아님을 표시한다. 급정지의 실제 최대 각도·출렁임을 엄밀하게 비교하려면 더 빠른 센서 원시 계측이나 외부 고속 카메라가 필요하다. 이번 배포는 센서를 새로 만들거나 ESP32 펌웨어를 변경/자동 업로드하지 않았다. PWM은 실제 서보 엔코더 각도가 아니며, 차분 가감속은 차체 가속도 IMU 실측이 아니다.

## 설치·실험 순서

1. 로봇을 정지하고 Windows 연결 창을 닫는다. 08 ZIP을 새 폴더에 전체 압축 해제한다.
2. `Setup-Jetson.cmd`로 앱/주행 프로세스를 업데이트한 뒤 `Install-HongikCafe.cmd`로 바로가기를 갱신한다. SSH 계정 암호는 설치 창에 직접 입력한다. 이번 작업에서 원격 SSH 키 인증은 되지 않아 자동 배포하지 못했다.
3. ESP32를 **Jetson USB 데이터 연결**로 연결한다. 서보 전원·공통 GND는 별도 확인한다. Arduino Serial Monitor 등 같은 포트를 사용하는 프로그램을 닫는다.
4. `ESP32 연결·영점 설정 열기` → USB 목록 → 실제 ESP32 포트 선택 → ESP32 연결. 서보 활성화, 실제 수평 영점, 보정 방향을 확인한다. 축 방향·서보 활성화·영점 저장은 자동 수행하지 않는다.
5. 지도·지점 이동 → 깊이 관측 연결 → 트레이/깊이 상태 확인. 우선 짧은 직진 검증(최대 12cm/s) 후 20cm/s 조건부터 제동 거리와 회전 위치를 확인한다.
6. 동일 출발 위치·방향으로 놓고 회차를 입력한 뒤 원하는 조건/속도 칸을 누른다. 30/40cm/s는 낮은 속도의 실제 제동·장애물 정지를 확인한 뒤 사용한다.
7. 실험 기록에서 결과와 자료를 확인한다. 저장된 각도 자료가 없는 시험은 각도 비교 자료로 취급하지 않는다.
