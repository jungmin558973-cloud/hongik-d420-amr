# HONGIK CAFÉ — 텔레옵·트레이 제어·주행 시나리오

ASUS에서 사용하는 로컬 Three.js GUI다. 시작은 **미리보기 / 실차 미연결**이다.
웹앱을 여는 것만으로 SSH 연결이나 모터 명령을 만들지 않는다.

## 열기

```bash
bash ~/d420_ws/scenario_lab/open.sh
```

바탕화면의 **HONGIK CAFÉ 주행 실험실** 아이콘으로도 실행한다. 앱처럼 주소창 없는 독립 Chrome 창을 열며, 서버는 같은 사용자 서비스로 유지한다. 터미널에서 같은 방식으로 열려면:

```bash
bash ~/d420_ws/scenario_lab/open.sh --app
```

실행 아이콘 원본은 `hongik-scenario-lab.desktop`이다. 앱 전용 브라우저 프로필과 로그는 `runs/app-profile/`, `runs/app-window.log`에 저장하며 일반 브라우저 프로필과 구분한다.

주소: <http://127.0.0.1:8765>
Ubuntu 사용자 서비스 `hongik-scenario-ui.service`로 실행하며 부팅 자동 시작으로 등록하지 않는다.
터미널을 닫아도 쓸 수 있고, 종료는 ASUS에서 아래 명령을 실행한다.

```bash
systemctl --user stop hongik-scenario-ui.service
```

미리보기만 실행할 때는 `bash ~/d420_ws/scenario_lab/start.sh`를 사용한다.
직접 서버를 열면서 실차 연결 버튼을 허용하려면 `--allow-real`을 붙인다.

## 조작 환경과 주행 방식

상단의 **시나리오 주행 / 텔레옵 수동 조종**으로 주행 방식을 바꾼다. 두 방식은 동시에 실행하지 않는다. **3D 미리보기 / 실차 시험**은 별도의 환경 선택이다.

수동 조종에서는 **수동 조종 켜기**를 누른 뒤 W/S 또는 ↑/↓로 전후진, A/D 또는 ←/→로 회전한다. 화면 방향 버튼도 누르는 동안 동작한다. 직진 3~30 cm/s와 회전 0.05~0.30 rad/s를 조절하며, 수동 조종 중에도 속도를 바꿀 수 있다. 키를 놓으면 해당 축을 즉시 0으로 명령한다. Space/Esc·창 포커스 이탈·입력 0.30초 만료는 수동 조종을 종료하며 다시 켜야 한다. 입력란에서 W/A/S/D를 타이핑하면 주행 입력으로 쓰지 않는다. 라이다는 화면 표시용으로 수신하며 장애물·후방 관측 범위를 이유로 주행을 막지 않는다.

## 트레이 3모드와 기울기 조정

| 앱 선택 | 동작 |
|---|---|
| 1 실행 안함 | 자동 보정을 끈다. 이미 켜진 서보의 현재 PWM은 유지한다. PWM 해제 버튼과 다르다. |
| 2 수평 유지 | ESP32의 100 Hz BNO055 피드백을 사용한다. 기존 펌웨어도 지원한다. |
| 3 예측 + 수평 유지 | 대기 중에는 수평 유지, 주행 중에는 예정 명령·입력 코스 모델의 목표각을 받아 로컬 IMU 피드백과 결합한다. 앱용 PROTO=2 펌웨어가 필요하다. |

실차에서는 **USB 목록 → ESP32 연결 → 두 서보 켜기 → 실제 수평에서 영점 저장 → 보정 방향 확인 → 모드 선택** 순서다. 앱의 선택/요청과 ESP32가 실제 보고한 모드는 따로 표시한다. 연결만으로 서보를 켜거나 모드를 바꾸지 않는다. 기존 보정 상태를 임의로 OFF라고 표시하지 않는다.

기울기 미세 조정은 **실행 안함** 상태에서 Roll −/+와 Pitch −/+ 버튼을 사용한다. 한 번에 PWM 10 μs를 바꾸며 각도 환산값이 아니다. 실제 트레이 각도는 BNO055 표시로 확인한다. 앱용 펌웨어는 미세 조정 후 영점/방향 확인을 무효화하므로 수평 기준을 다시 등록한다. 주행 중에는 모드·영점·USB 연결을 바꾸지 않는다.

예측은 **RealSense 깊이 영상 분석이 아니다.** 예정된 가감속·회전 명령과 사용자가 입력한 언덕 형상만 사용한다. 시나리오는 현재 위치에서 계획을 짧게 전개하며 미래 센서값·액체 상태를 읽지 않는다. 텔레옵은 현재 눌린 명령의 응답만 계산하며 미래 키 입력이나 예고 없는 정지를 선행 인지하지 않는다. 기본 선행 0.20 s, 목표각 제한 5°이며 범위·축 부호·축 맞바꿈을 조정할 수 있다. 이 값은 하드웨어 최적값이 아니다. 미리보기의 트레이 동작은 기구학 표시이며 실제 센서값과 구분한다.

앱용 소스: `firmware/esp32_app_control/esp32_app_control.ino`. 원래 `firmware/esp32_new_ver/`는 보존한다. 상세 준비와 빌드는 [펌웨어 안내](firmware/README.md), 전체 사용 순서는 [조종 앱 사용법](docs/조종앱_사용법_20261025.md)에 있다. 앱에서도 펌웨어를 내려받을 수 있다. 실물 ESP32에 한 번 업로드해야 PROTO=2가 수신되고 실차 예측 버튼이 활성화된다. 앱에서 자동 플래시하지 않는다.

## 시나리오 거리와 속도

| 카드 | 출발선 기준 동작 |
| --- | --- |
| 1m 후 급정지 | 완만한 출발 가속 후 설정 속도를 유지한다. 1.00m에서 감속 제한을 우회해 0 속도 명령을 보내고 실제 정지 응답을 관찰한다. |
| 1m 후 90° 턴 | 1.00m 직진 후 전진하며 좌/우 90° 선회하고 정지한다. 기본 반경 35cm, 각속도 최대 0.25rad/s이며 yaw 피드백으로 종료한다. |
| 1.2m + 언덕 10cm | 1.05m부터 감속, 1.20m에서 언덕 진입, 총 1.30m에서 정지한다. 언덕 구간은 최대 5cm/s다. 언덕 전체를 넘어가는 시험이 아니다. |

기본 8cm/s, 범위 3~30cm/s다. 사용자 요청으로 최대 선속도를 0.30m/s로 확장했다. 최대 각속도는 0.30rad/s다.
1.00m/1.30m는 **출발 가속 구간을 포함한 실제 이동 거리 기준**이며 타이머로 대략 이동하지 않는다.
오도메트리 오차와 차체 제동 응답이 있으므로 실물 거리·각도는 별도로 실측해야 한다.

### 언덕 치수와 출발선

사용자 제공 값은 **경사각 15°, 폭 60cm, 길이 80cm**다.
사용자가 **한쪽 경사판 표면 길이 80cm**임을 확인했다. 이 기준을 기본값으로 저장했고 다른 기준도 GUI에서 구분한다.

| 길이 기준 | 전체 수평 길이 | 최고 높이 |
| --- | ---: | ---: |
| 삼각형 전체 바닥 길이 80cm | 80.0cm | 약 10.7cm |
| 오르막 한쪽의 수평 길이 80cm | 160.0cm | 약 21.4cm |
| 기울어진 경사판 표면 길이 80cm — 확인된 기본값 | 약 154.5cm | 약 20.7cm |

화면은 대칭 삼각형 단면의 언덕을 사용한다. 확인된 기본값에서 높이는 `0.80 × sin(15°) ≈ 0.207m`, 한쪽 수평 길이는 `0.80 × cos(15°) ≈ 0.773m`다. 대칭 형상의 전체 수평 길이는 약 1.545m다.
첨부 `IMG_4074.MOV`는 경사판 외형 참고이며 영상 픽셀로 치수를 추정하지 않았다.
사이드바의 영상 캡처에는 **실시간 영상 아님** 표시가 있다.

출발선은 연결/등록 시점의 **앞바퀴 축 위치**다. CAD 차체 중심은 그 선의 13.5cm 뒤에 그린다.
실제 언덕의 시작 모서리를 출발선 1.20m에 정렬한다. `출발선 설정`으로 정지한 현재 위치·방향을
다시 등록할 수 있으며, 등록만으로 모터 명령을 보내지 않는다.
시험이 끝났다고 화면의 차 위치를 원점으로 되돌리지 않는다. 다음 실차 시험은 출발선으로
돌려놓거나 출발선을 새로 등록한 뒤 진행한다. 출발선에서 5cm/5° 이상 벗어나면 시작을 거절한다.
언덕의 위치도 새 출발선에 맞춰 다시 정렬해야 한다.

**세 번째 시험의 끝은 경사판 위다.** 0 속도 명령이 실제 차체의 경사면 주차 제동을 보장하지 않는다.
실물 정지 유지·뒤밀림을 확인하고, GUI의 실측/정렬 확인란을 체크한다. 후퇴가 감지되면 시험을
중단하지만 소프트웨어만으로 미끄러짐을 막을 수는 없다.

## K221에서 실차 연결

저장된 기본 주소는 마지막 K221 연결에서 확인한 **`seo@192.168.0.47`**이다. 다음 연결 때 IP가 유지된다는 보장은 없다.
ASUS와 Jetson을 K221에 연결하고 Jetson 전원을 켠 뒤:

1. GUI의 Jetson SSH 주소 확인 → **실차 연결 준비**.
2. 오도메트리·라이다·RealSense 영상이 수신돼 준비 상태가 될 때까지 기다린다.
3. 필요하면 **출발선 설정** → **실차 시험**.
4. 실제 공간과 언덕 배치를 확인한 뒤 카드를 누른다. 약 1.5초 준비 표시 후 이동한다.

주소가 바뀌면 GUI 입력란에 현재 IP 또는 `SJM.local`/`hongik-jetson`을 입력한다.
기존 Jetson 호스트 키를 `HostKeyAlias=192.168.0.12`로 계속 확인한다. 키 확인을 우회하거나
비밀번호를 저장하지 않는다. `D420_HOST` 환경변수로 기본 주소를 바꿀 수도 있다.
밖에서 GUI를 여는 것만으로 K221 내부 IP에 연결되는 것은 아니다. VPN/공유기 외부 접속은 추가하지 않았다.

기존 WASD 창은 Q로 닫는다. 다른 명령 발행자가 있으면 연결 준비/실행을 거절한다.
`준비`는 SSH로 기존 세션을 정리하고 장치·센서 서비스를 시작하는 단계이며 주행 목표를 보내지 않는다.
실제 비영 속도는 사용자가 **실차 카드**를 누른 후에만 발생한다.

## 실시간 화면의 데이터

- **차체 XY/yaw:** 실제 `/odom`을 출발선 좌표로 변환한다. 정지/시험 대기 중에도 실제 위치를 갱신한다.
  실차 모드의 모델을 명령 속도나 경과 시간으로 움직이지 않는다.
- **RealSense RGB:** Jetson `/camera/camera/color/image_raw/compressed`를 우선 수신하고,
  없으면 `/camera/camera/color/image_raw`를 수신해 별도 스레드에서 JPEG로 변환한다.
  `/api/camera.jpg`로 실제 최신 프레임만 제공한다. 미연결/오래된 영상은 대기 표시로 바꾼다.
- **라이다 지도:** Jetson의 SLAM `/map`을 PNG로 변환하고 `map → odom → 출발선` 변환으로
  3D 바닥에 겹친다. 별도 2D 패널에도 지도와 차체 방향을 표시한다.
- **현재 스캔:** `/scan`을 `base_footprint`로 변환해 차체 주변에 표시한다. 2026-10-25 사용자 요청으로 장애물 자동 정지와 후방 관측 범위 주행 제한은 해제했다.
- **높이·pitch:** 실측 IMU가 연결되지 않았으므로 입력한 언덕 형상과 XY로 추정해 표시한다.
  화면에도 **XY/yaw: Odom · 높이/기울기: 코스 형상 추정**이라고 구분한다.
- 제공된 실물 트레이 코드는 ESP32-S3 + **BNO055**다. 사용자 확인으로 BNO055는 움직이는 트레이
  아래에 장착돼 함께 기울어진다. 이후 측정값은 트레이 자세에 사용하며 차체 pitch/roll과 구분한다.
  GUI에는 Jetson USB 장치 선택, ESP32 상태 수신과 명시적 서보/수평 제어 요청 코드가 있다.
  실제 ESP32 연결·주행 통합 검증은 아직이며, 물 유출량은 측정하지 않는다.

미리보기는 기구학적 시각 예시다. 첨부 ZIP의 Isaac Sim·PhysX 시험이나 유체 시뮬레이션으로
바뀐 것이 아니며, 프리뷰 수치를 실차 성능으로 해석하지 않는다.

## 장치 세션과 중단

`브라우저 → ASUS 제어 서버 → ROS 2 Domain 120 → Jetson 기존 D420 브리지` 구조다.
SSH는 세션 배포·시작에, ROS 2는 명령/센서 전송에 사용한다. 장치를 다시 켠 이후에도 브라우저에서 준비할 수 있다.

`prepare_robot.sh`는 기존 Nav2/클릭 서비스를 중지하고 주행 명령 중복을 검사한다.
SLAM이 실행 중이면 먼저 새 파일명으로 지도·포즈 그래프를 보관한다. 저장 실패 시 기존 SLAM을 중지하지 않는다.
그 뒤 기존 센서 세션을 중지하고 별도 경로에 이번 파일만 배포한다. 이전 배포본은 시간별 백업한다.
임시 `hongik-scenarios.service`는 브리지·C1·URDF·RealSense RGB·표시용 SLAM을 실행한다.
SLAM은 화면용이며 시나리오 주행에 Nav2/저장 지도는 필요하지 않다.

기존 부팅 서비스 `hongik-robot.service`의 enabled 설정은 유지한다. 다음 부팅은 기존 읽기 전용 구성이다.
원래 프로그램·제조사 코드·보관 지도를 덮어쓰지 않는다. 이번 변경 전 사본은 `backups/`에 있다.

상단 정지 버튼, 오른쪽 중지, Escape/Space로 중단한다. 실차 탭 숨김/종료, heartbeat 0.8초 초과,
센서/영상 지연, 제어 주기 지연, 원점 점프, 후진/방향 불일치, 이동 무응답은 중단 조건이다.
0.25초 브리지 watchdog을 유지한다. 사용자 요청에 따라 장애물 근접점과 후방 관측 범위로
주행을 차단하지 않는다. 중단 뒤 자동 재출발하지 않는다.

실험 종료: 먼저 중지 → ASUS 서버 종료 → 필요하면 원래 모드로 복귀한다.


## 검증

```bash
cd ~/d420_ws
PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 python3 -m pytest -q scenario_lab/tests
node --input-type=module --check < scenario_lab/web/app.js
bash -n scenario_lab/start.sh scenario_lab/open.sh scenario_lab/prepare_robot.sh scenario_lab/jetson/start.sh
```

제어·영상·지도·API 모의 테스트와 실제 Chrome의 키보드/포인터 및 세 프리뷰 실행을 확인했다. 이번 검증 수치와 출처는 `docs/operator_validation.json`, `qa/operator_modes/`에 기록한다.
별도 합성 센서 서버로 **명령을 보내지 않아도 위치 입력에 따라 모델이 움직이는 것**, JPEG 패널,
SLAM 텍스처 표시도 확인했다. `qa/synthetic_media*`는 합성 데이터 검사이며 실제 센서 촬영이 아니다.
현재는 사용자가 Jetson을 가져오지 않은 외부 환경이므로 최종 실차 연결/영상/주행 검증을 하지 않았다.

Python 3.10/aiohttp/Pillow/NumPy, ROS 2 Humble/rclpy와 로컬 Three.js 0.180.0(MIT)를 사용한다.
Three.js 라이선스는 `web/vendor/THREE-LICENSE.txt`에 있다. CAD는 기존 `d420_description` 사본이다.
참고: [Three.js 공식 모듈 안내](https://threejs.org/manual/pages/installation.html).
