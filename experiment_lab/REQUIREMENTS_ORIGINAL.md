# Codex 개발 요청: HONGIK CAFE D420 통합 실험·계측·최적화 시스템

당신은 ROS2 Humble, Jetson Orin Nano, Windows/Python/OpenCV, Flask 또는 기존 웹앱, 로봇 주행 안전 시스템을 다루는 시니어 로보틱스 엔지니어다. 지금부터 **기존 HONGIK CAFE 코드베이스를 최대한 재사용하고 안전하게 확장**하여, 학부 기계시스템종합설계 프로젝트를 위한 **실험 시나리오 자동 실행 + Windows USB 카메라 동시 녹화 + Jetson 원시 주행/트레이 로그 수집 + 시간 동기화 + 실시간 시각화 + Google Drive 업로드 + 실험 결과 기반 제어 파라미터 추천** 시스템을 실제 동작하는 코드로 구현하라.

## 0. 진행 원칙 — 가장 중요

1. **먼저 실제 프로젝트 파일을 열어 구조를 확인하라.** 현재 파일 이름, ROS 토픽, HTTP API, ESP32 PROTO, 브리지 메시지 포맷을 추측하거나 존재하지 않는 API를 지어내지 말 것. 코드를 확인한 뒤 `RECON_REPORT.md`에 실제 동작 경로, 기존 구현 상태, 부족한 부분, 테스트 상태를 기록하라.
2. 기존 원격주행·지도·Nav2·L자 시험·트레이 UI를 삭제하거나 망가뜨리지 말라. Git 브랜치/백업을 만들고 변경은 독립 모듈로 격리하라. 최신 버전과 백업 버전의 차이를 비교하라.
3. **실제 로봇 명령은 기본 비활성**. 개발·테스트는 mock/replay/dry-run으로 먼저 실행하고, 사용자가 로봇 옆에서 안전 점검 후 명시적으로 ARM하고 실험 시작을 눌렀을 때만 이동하도록 하라. 개발 과정에서 임의로 실제 주행을 시작하지 말라.
4. 사람과 장애물의 안전이 음료의 출렁임 억제보다 항상 우선이다. 물이 넘치는 것을 막으려고 충돌방지/긴급정지를 늦추거나 무시하는 기능을 만들지 말라. 센서 오류·로봇 연결 끊김·주행 데이터 지연·원격 명령 중복·거리 초과 시 안전정지/실험 중단.
5. 완성되지 않은 부분을 구현했다고 말하지 말 것. **모의 시험 통과, Windows 실기기 확인 필요, Jetson 실차 검증 필요**를 분리해 보고하라. 외부 Drive 인증도 자동으로 있다고 가정하지 말 것.
6. 핵심 기능을 실제 동작시키는 것이 목적이다. 설명·UI 목업만 만들지 말고 서버, 프론트엔드, 수집기, 제어 연동, 저장, 테스트, 사용자 실행 스크립트까지 작성하라. 진행 중 막히더라도 작동 가능한 범위까지 구현하고 미완성 항목을 명시하라.

## 1. 기존 환경 및 확인할 실제 소스

- 프로젝트: HONGIK CAFE / D420 4WD 음료 배달로봇. 최종 검증 목표는 **급정지·회전·경사에서 뚜껑 없는 음료를 흘리지 않는 것**. 첫 단계는 직진·감속·정지 실험.
- Windows ASUS 노트북: Logitech C920e USB 웹캠을 **급정지 구간을 향해 고정 설치**. 영상 촬영/저장, GUI, 실시간 출렁임 OpenCV 분석. 일반적으로 FHD 30fps 또는 720p 30fps부터 시험.
- Jetson Orin Nano: Ubuntu/ROS2 Humble, `ROS_DOMAIN_ID=120`, SLAMTEC C1 LiDAR, RealSense D435, D420 STM32 커스텀 차체 제어보드(기존 CH340 USB-UART 115200bps), 오도메트리/주행 노드. 차량-USB는 **기존 소유 프로세스 단일화**, 새로운 프로그램이 직렬 포트를 중복 열지 말 것.
- ESP32 + BNO08X: 2축 짐벌 트레이 Roll/Pitch. 기존 ESP32 `PROTO=2` 및 트레이 OFF(PWM 유지), LEVEL, PREDICTIVE+LEVEL 관련 구현이 있음. 각도/서보 명령/실측/캘리브레이션을 실제 코드에서 확인할 것. 서보 전원 안전은 프로그램과 별개로 유지.
- 기존 Windows → Jetson 접속: `Open-HongikCafe.cmd` 및 SSH 터널, 기존 대시보드 예시 `http://127.0.0.1:18765/navigation`; IP/경로는 `connection.json`과 실제 설정에서 읽고 하드코딩 금지.
- 기존 소스 백업 폴더: https://drive.google.com/drive/folders/1cjH8Q4XZI-BAKNUK3quQK2gk_RwC477n
- 전체 소스 ZIP: https://drive.google.com/file/d/1arVpDst5cm8rD71Lx3tHoyGvA6YR4o6c/view
- 2026-11-16 Windows 실험 패키지: https://drive.google.com/file/d/1kZRE0z25H4UatxLoMG0xzAzMzVb4vaU9/view
- 2026-11-16 L자/급정지 안내: https://drive.google.com/file/d/1jnd68GsMGBcK3p3XjhlEC25S9u7kAB9k/view
- 원래 소스에서 우선 조사할 폴더/파일: `scenario_lab/`, `scenario_lab/start.sh`, `scenario_lab/tests/`, `scenario_lab/team_access/windows/`, `scenario_lab/team_access/systemd/`, `external/d420_ros_integrated/`, `src/`, `config/`, `diagnostics/`, `maps/`, ESP32 펌웨어, 기존 실험 엔진과 상태 API. 경로가 다르면 실제 구조를 우선하라.
- 기존 작업 기록에 따르면 수동 WASD 실차 주행은 성공, **0.12m/s·60cm 짧은 시험**이 안전 검증 기준. L자 기본 0.12m/s, 기존 L자 시험 상한 0.20m/s, 0.40m/s 실제 주행은 **검증 안 됨**. 2026-11-16의 급정지는 `0 속도 명령`이며 물리적 즉시정지를 보장하지 않는다. 저장 지도 정확도도 미검증. 이런 한계를 모두 존중하라.
- 이전 독립형 영상 분석기에서 ROI가 컵이 아닌 배경을 추적하는 버그가 발생했음. 반드시 **컵 등장 시각 지정, 미리보기 시점 이동, 액면 ROI 마우스 드래그, 컵 추적 앵커(뚜껑 등) 별도 드래그** 기능을 통합하라. 추적 신뢰도가 낮으면 값을 꾸며내지 말고 `invalid/NaN` 기록. 실제 액면과 시각적으로 맞는지 반드시 미리보기 제공.
- 이전 Windows C920e 실험 앱에서 OpenCV 카메라 열기 실패와 `Unknown C++ exception` 및 `Failed to fetch` 문제가 있었음. Windows 카메라 열기 시 DirectShow/MSMF 선택과 장치 인덱스 진단, 타임아웃, 캡처 프로세스 격리, 실패 후 서버 생존/재연결, 점유 중인 카메라 안내를 포함하라.

## 3. 정확한 자동 실험 동작

- `실험 시작`을 누르면 먼저 안전 사전 점검(카메라/기록/Jetson/odom/센서/실험 공간 비움/사용자 ARM/주행 최대속도), 시계 오프셋 측정 → 실험 ID 생성 → Windows 비디오 녹화 및 Jetson 고속 로그 기록 시작 확인 → 프리롤 2~3초 → Jetson에 **딱 한 번** 시나리오 시작 명령.
- 기본 전진 실험: 선택한 **1.5m 또는 2.0m의 실제 주행거리**를 목표로, 선택한 속도 프로파일에 따라 출발→정속(도달 가능 시)→감속/정지→정지 검증→액면 안정화 대기(예: 3~5초 또는 검출 임계값)→원점으로 후진 복귀(선택 시)→완전 정지→포스트롤 녹화→자동 저장.
- 사용자 요청의 '후진 2m'는 **2m 실험에서만 2m 복귀**가 자연스럽다. 1.5m 전진인데 무조건 2m 후진하면 시작점을 넘어 위험하므로, 기본 복귀는 **실제 이동한 거리만큼 원점으로 돌아가기**, 별도 후진 2m 실험은 명시 설정/안전 검증을 거쳐 별개 시나리오로 제공. 후진 궤적에도 고유 실험구간 ID를 부여하여 액면 데이터를 분리하고 합산 점수도 제공.
- 거리 계산은 오도메트리 기반으로 하되 기준 원점과 진행 방향 축을 기록하고 단순 적분 오차/미끄러짐을 경고. **명령된 정지 시점과 실제 멈춘 위치는 다르다.** 목표 거리와 실제 거리, 정지 명령 지점, 정지 완료 지점, 초과거리, 오차를 따로 저장하고 보정된 브레이킹 트리거로 정지 오차를 줄이는 기능은 안전 시험 후 활성화.
- S-curve OFF: 기존에 안전하게 동작하는 기본 가감속/선형 프로파일(실제 기존 구현 확인). S-curve ON: **jerk 제한된 가속도·속도 프로파일**. 정해진 거리에서 목표 속도에 못 미칠 수 있으므로 삼각형/사다리꼴/7-segment S-curve 등 거리 적합 계산 및 시간/속도 제한을 정확히 구현. 원본 `/cmd_vel` 요청·제한 후 최종 명령·실제 `/odom` 속도를 각각 로그. 최종 안전정지는 어떠한 S-curve 필터보다 우선.
- 트레이 OFF(출렁임 제어 없음; 필요한 경우 기존 PWM 유지), LEVEL(BNO08X 수평 유지), PREDICTIVE(주행 명령/예정 감속 시점과 실제 감속 신호로 선제 기울기 보상 + 안전한 수평 복귀). 예측 보상은 독립 설정값(최대 각도, 시작 리드 타임, gain, 램프 시간, 최대 각속도, 필터, 중심 보정, 서보 출력 제한)을 제공. 실제 서보 모터 방향/타임스탬프/성능 검증 전 실차 활성화 금지. 기존 펌웨어/하드웨어 능력에 맞춰 구현하되 불가능한 값은 명시적으로 제한.
- 별도 실험 유형으로 '계획된 정지'와 '갑작스러운 장애물로 인한 안전정지 모의실험'을 구분. 실제 사람을 갑자기 튀어나오게 하지 말고 안전한 모형 장애물/신호 주입으로 수행. 안전정지 회피·지연 금지.
- 네트워크 장애, 카메라 미연결, 오도메트리 오래됨, USB 브리지 문제, 트레이 오류, 구동 최대시간 초과, 허용 거리/속도 초과 시 **차체 독립 안전정지 + ABORT 로그 + 가능한 데이터 보존**. Windows 앱만 종료돼도 Jetson이 안전하게 정지하도록 timeout/watchdog 구현. 카메라 영상이 주행 중 시야 밖이라면 액면 `invalid`, 주행 로그는 계속 기록.

## 4. 실험 행렬과 반복 자동화

기본 설정을 2(거리: 1.5/2m) × 3(속도: 0.20/0.30/0.40m/s) × 2(S-curve OFF/ON) × 3(트레이 OFF/LEVEL/PREDICTIVE) = **36조건**으로 생성하라. 각 조건 3회 반복 시 총 108실험. 단, 안전 검증된 속도에 해당하는 실험만 활성화하고 0.30/0.40m/s는 안전 승인 전 대기 상태로 표시하라.

UI에 A~F 빠른 모드:
- A: S-curve OFF + 트레이 OFF (기준군)
- B: S-curve ON + 트레이 OFF
- C: S-curve OFF + 트레이 LEVEL
- D: S-curve ON + 트레이 LEVEL
- E: S-curve OFF + 트레이 PREDICTIVE
- F: S-curve ON + 트레이 PREDICTIVE

실험 큐를 만들고 완료된 시험은 중복하지 않으며, 수동 확인 후 다음 시험으로 넘어갈 수 있게 하라. **무인 연속 주행은 기본 금지**: 컵 재충전/안전 확인/원점 위치 보정이 필요할 수 있으므로 매 반복 또는 묶음 사이에 사용자 확인 게이트를 둔다. 동일 수위·컵·거리·카메라 조건을 기록하고 실험 조건을 랜덤화할 수 있게 하여 순서 효과를 줄여라. 항상 속도를 실제 측정값과 함께 보고.

## 5. 모든 접근 가능한 신호 수집 — 없으면 없는 그대로 표시

Jetson에서는 ROS2 `rosbag2` + 구조화된 이벤트/메시지 로그를 수집하라. 단, 실제 존재하는 topic/interface 목록을 런타임에서 검색한 후 구독하고 동적으로 매핑; 다음 이름은 후보이며 확정 API가 아님:
- `/cmd_vel` 원본/필터 후 최종 명령, 현재 명령 소유자, 자동/수동/안전정지 모드, 시나리오 step/state, 시작/종료 이벤트, 브레이크 요청 시점, 안전정지 사유
- `/odom`: pose x/y/yaw, twist x/y/angular z, wheel feedback가 실제 있다면 wheel rpm, 속도·가속도·jerk의 추정값과 필터 품질
- 라이다 C1 스캔, D435 장애물 거리/센서 상태, Collision Monitor/Nav2 또는 기존 DeepRoute 안전 이벤트(실제 있는 경우)
- ESP32 BNO08X의 Roll/Pitch 및 유효성, 트레이 모드, 서보 PWM 명령, 예상 기울기, 계산된 보상, 클램핑, 시간 지연; 실측 각도가 없다면 명령과 분리하여 명시
- 메시지 발행/수신 시각, ROS stamp, 시퀀스, 결측/지연, 상태 머신 이벤트
- 실제 모터 전류·배터리 전압·브레이크 피드백·차체 IMU가 제공되지 않으면 **임의 생성 금지**, 미지원으로 표시하고 나중에 확장 가능한 스키마 준비

Windows C920e에서는 원본 영상과 프레임별 캡처 타임스탬프(perf_counter/monotonic + UTC 대응), 실제 fps, 드롭 프레임 수, ROI/검출 품질과 계산 지표를 저장. 네트워크 로그 폴링은 보조 UI로 쓰고, **원시 ROS 메시지는 Jetson에서 직접 기록**할 것(HTTP 10Hz 샘플만으로 모든 명령 이벤트를 보존한다고 주장 금지).

## 6. 영상/OpenCV 분석 요구

- 카메라는 **Windows에 USB 연결되고 벽/삼각대에 고정**, 영상 및 ROI는 Windows에서 처리. Jetson USB 영상 입력을 요구하지 말 것.
- 컵이 등장하는 시점을 슬라이더/프레임 이동으로 선택. 영상에서 드래그로 `액면 ROI`와 `뚜껑/컵 윤곽 추적 앵커`를 따로 지정하고, 움직이는 컵에 따라 ROI 자동 이동. 스케일 변경/가림/추적 손실 시 재탐색과 낮은 신뢰도 표시, 무관한 의자/콘센트/그리드 패턴으로 ROI가 옮겨가면 검출값 폐기.
- 우선 측정 지표: 왼쪽/중앙/오른쪽 액면 높이(px), 최고 액면(px), Δh(좌우 차이), 기준 수면 대비 최대 편차/peak-to-peak/RMS, 좌우 비대칭, 허용선까지 여유, 정지 후 안정화 시간, 진동 주파수(적절한 프레임·측정 시간 확인), 검출 성공률, 가능 시 뚜껑 접촉 **영상상 추정 이벤트**. 실제 물이 뚜껑에 닿았다고 보장하지 않고 검증 플래그 기록.
- 격자와 투명 컵 굴절에 주의. 컵 내부 영역 마스크, 조명/색상/배경별 threshold 설정, 수동 보정과 시각화. 픽셀→mm 변환은 같은 깊이 평면의 실제 기준 길이/카메라 보정 후에만 하고, 보정 전 mm 수치를 표시하지 말 것.
- 고정 카메라 시야 밖에 로봇이 있으면 검출 `not visible`, `valid=false`; 그 구간은 액면 통계에서 제외하되 주행 기록과 영상은 보존. 원본 영상·검출선 영상·프레임별 CSV 저장.
- 실시간 분석은 최신 프레임 우선 큐/캡처 프로세스 격리로 프레임 밀림 최소화. 화면 FPS와 실제 카메라 FPS, 지연시간 분리 표시. 과부하면 영상은 계속 녹화하고 분석 frame skip 또는 사후 정밀 분석으로 전환.

## 7. Windows-Jetson 시간 동기화

서로 다른 PC이므로 **단순히 '실험 시작 버튼을 함께 눌렀다'고 시간 동기화가 완성되지 않는다.** Windows 카메라 timestamp와 Jetson ROS/monotonic 타임스탬프를 모두 원본으로 저장. 연결 전에 복수 핑/왕복시간으로 클록 오프셋·불확도 추정, 가능하면 chrony/NTP와 공통 UTC 사용, 시작/정지/단계 변경 이벤트를 양쪽에 기록. 선택적 LED/화면 플래시 영상 마커 또는 ROS 이벤트로 지연 검증.
- 프레임과 원시 센서 데이터는 각각 보존. 동기 통합 CSV는 명시적 30Hz 등 타임라인으로 보간/최근접 매칭하되 보간 여부, 시간차(ms), 품질 플래그를 포함.
- 네트워크 지연을 물리적 모터/서보 응답 지연으로 오인하지 말 것. 동기화 품질이 낮으면 정확한 반응시간 수치 대신 '동기화 불확실' 표시.

## 8. 데이터 저장 구조·Google Drive 업로드

로컬 저장을 1순위로 해서 실험 중 인터넷이 끊겨도 손실되지 않도록 하라. 모든 실행에 고유 run_id를 부여하고, 예를 들면:

```text
experiments/
  2026-11-20/
    RUN_20261120_001_2m_20cms_SON_LEVEL/
      config.json
      manifest.json             # 파일 SHA-256, 상태, 시계 오프셋
      events.jsonl              # 주행/정지/중단/안전 이벤트
      webcam_raw.mp4
      webcam_annotated.mp4
      camera_frames.csv
      robot_telemetry.jsonl
      rosbag2/
      synchronized.csv
      metrics.json
      report.html
      plots/                  # velocity, brake, tray, slosh, comparison
```

실험 종료 직후 파일 close/fsync/해시 검증/로컬 DB 메타데이터 업데이트 후 **Google Drive 사용자 지정 폴더**에 `run_id`별 폴더로 업로드. Drive OAuth 사용(사용자가 직접 인증), 토큰 안전 보관, 업로드 큐/재시도/중복방지/해시 검증/성공 확인/진행률/실패 표시. API 인증이 안 된 상태에서는 프로그램 사용을 막지 말고 로컬 저장 후 `업로드 대기`로 남겨라. 토큰·비밀번호를 소스 코드, 로그, ZIP, 공개 저장소에 포함하지 말라.

실험 전체를 검색할 수 있는 SQLite 또는 기존 DB `experiment_index`를 만들고 날짜/시나리오/속도/거리/트레이/수위/결과/업로드 상태를 조회하도록. 보고서와 CSV·영상·rosbag2 모두 동일한 run_id에 연결.

## 9. 분석·추천 버튼(실험 결과에 근거한 추천)

'결과 분석' 클릭 시 단일 시험에서 전진/후진 별도로 최고 액면변위, RMS, peak-to-peak, 흔들림 발생/안정화 시간, 정지 명령~실제 정지 지연, 실제 정지거리와 오차, 평균/최대 가감속, jerk, 트레이 Roll/Pitch 최대값·RMS, 검출 유효율, 전체 주행시간을 계산하여 큰 KPI 카드와 타임라인 그래프로 보여줄 것.

'조건 비교'는 반드시 **같은 목표 거리·같은 실제 속도 범위·컵 종류·수위·카메라 세팅·실험 구간·실제 정지 거리**를 고려해 그룹 비교. 평균·중앙값·표준편차, 각 조건 반복 횟수, 이상치, 데이터 품질을 함께 제공. 1회 실험만으로 '이게 최적'이라고 결론 내리지 말 것.

'추천값 분석' 버튼은 저장된 반복 시험 데이터를 이용해 **정지 안전거리/충돌방지 제약을 만족하면서** 출렁임 최소, 안정화 시간 최소, 주행시간 과도 증가 방지를 목표로 다음 시험 파라미터를 추천:
- 목표 주행 속도
- 감속 개시 위치/시간, 가속도 상한, 감속도 상한, jerk 제한, S-curve 유연도/시간 비율
- 트레이 모드 LEVEL 또는 PREDICTIVE, 예측 리드타임, 보상 gain/최대각/복귀 속도
- 추천 근거(같은 조건의 이전 시험 목록, 예상 효과 범위, 안전 제한, 데이터 신뢰도)

처음에는 규칙 기반 + 그룹별 성능 비교 및 범위 내 그리드 탐색을 구현. 충분한 데이터와 반복 시험이 쌓인 후 **제약조건 기반 베이지안 최적화** 옵션을 추가할 수 있게 모듈화. 강화학습은 미래 확장으로만 표시; 오프라인 데이터만으로 실차 RL을 완성했다고 주장하지 말 것. 추천값은 자동으로 로봇에 적용하지 않고 사용자가 **적용 승인**을 눌러야 다음 실험 설정으로 반영.

## 10. UI 디자인·운영

- 기존 홍익 카페의 딥그린/크림/우드 톤을 유지한 한국어 대시보드, 모바일은 모니터링 가능하지만 실차 자동 주행 승인/조작은 안전한 화면에서만 허용.
- 실험 시나리오 설정, 6개 모드 카드, 1.5/2m, 20/30/40cm/s, 수위/컵 정보, 상태 스텝, 실시간 C920e 영상, 액면 추적 오버레이, 4종 그래프(액면/속도/감속·제동/트레이), 결과 카드, 지난 실험 테이블, 비교 그래프, Drive 업로드 큐를 보기 쉽게 배치.
- 상태 표시: `READY`, `RECORDING`, `ARMED`, `MOVING`, `BRAKING`, `SETTLING`, `RETURNING`, `SAVING`, `UPLOADING`, `COMPLETE`, `ABORTED`, `ERROR`. 어떤 상태에서 어떤 버튼이 가능한지 서버 상태 머신에서 강제.
- 카메라 연결 오류는 브라우저 `Failed to fetch`만 띄우지 말고 원인(장치 번호/다른 앱 점유/지원하지 않는 FPS/프로세스 종료)을 보여주고 캡처 워커만 복구. 서버와 다른 로그는 살아 있어야 함.
- 장치·제어 모드·속도에서 미확인 값은 `N/A`, `미검증` 표기. 사용자가 실험 이름/메모 입력 가능.

## 11. 개발 단계·검증·납품

**1단계(무구동 테스트):** 기존 코드 조사, 안전한 신규 실험 페이지, Windows 카메라 디바이스 진단, 수동 ROI/영상 녹화, mock Jetson 수집기, 파일 저장 및 Drive 업로드 큐.

**2단계(로그 연동):** 기존 Jetson 상태 API/ROS2 bridge 연동, 실제 topic discovery, rosbag2, 이벤트/타임스탬프 동기, 샘플 영상 및 mock 주행 신호 replay, 45개든 78개든 임의 개수 채우지 않고 신뢰 가능한 실제 수집 항목 목록 보고.

**3단계(안전한 자동 주행):** 0.12m/s·짧은 거리 검증 시나리오, 물리 STOP과 watchdog 테스트, 거리 오차 측정, 자동 왕복; 이후 검증된 0.20m/s → 승인 시 0.30/0.40m/s 순차 활성화. 자동 주행 없이도 기록 전용 모드 상시 사용 가능.

**4단계(실험 행렬/분석):** A~F 조합 및 1.5/2m 실험 큐, 실시간 OpenCV KPI, 비교/추천, Drive 업로드/복구, 보고서.

**5단계(선택):** 조건 검증 후 PREDICTIVE 트레이 제어와 S-curve 파라미터 자동 추천(적용은 사용자 승인), 추가 급정지 모의 시나리오.

반드시 테스트 작성:
- 단위: S-curve 거리/속도/jerk 제약, 거리/복귀/정지 상태 머신, 모드 조합 생성, KPI 공식, 타임스탬프 merge, 추천값 안전 제한.
- 통합: mock camera/Jetson/ESP32, 네트워크 단절, 카메라 0 실패, ROI 오검출, 중도 취소, 재시작 후 파일 복구, Drive 업로드 실패/재시도, 브레이크와 모터 명령 소유권 충돌.
- UI: 타임 슬라이더, 박스 드래그, 조건 선택/저장/실험 큐, 상태/오류, 그래프와 데이터 다운로드.
- 실기기: 실제 Windows C920e, Jetson ROS2, ESP32, 로봇을 **별도 검증 단계**로 남기고 사용자가 현장에서 시험하도록 명령과 체크리스트 제공. 테스트했다고 거짓 주장 금지.

**최종 납품물:** 실행 가능한 변경 소스/패치, Windows 원클릭 실행기(한글 BAT 인코딩 오류 없는 영문 명령으로 구현), Jetson 설치/시작 스크립트, `.env.example`(토큰 제외), dependency lock/requirements, 마이그레이션/롤백 방법, `README_실험방법.md`, 안전 체크리스트, 실제 ROS 토픽/API 매핑 표, 샘플 replay 영상·가짜 ROS 로그, 단위/통합 테스트 결과, 실패/미검증 기능 목록, 사용자 GUI 스크린샷, 실제로 생성된 예시 실험 폴더.

코드를 변경하기 전에 **(1) 발견한 실제 구현 현황 (2) 수정할 구체 파일과 구조 (3) 안전 게이트 (4) 단계별 구현 계획**을 짧게 제시하고, 그다음 사용자가 이미 요청한 범위는 불필요한 재확인 없이 가능한 데까지 실제 구현하라. 백업과 기존 실차 제어는 보존할 것.
