# HONGIK CAFÉ 지도 작성과 저장 지점 이동

2026-11-07. ASUS 콘솔: <http://127.0.0.1:8765/navigation>.
Jetson Orin Nano: `ssh hongik-jetson` → `seo@192.168.0.47` (K221).

## 사용 순서

1. 차체 배터리와 Jetson을 켠다. 기존에 동작했던 리모컨 꺼짐 상태를 유지한다.
2. 지도 화면의 **새 지도 작성 연결**을 누른다. 기존 SLAM이 실행 중이면
   지도와 포즈 그래프를 먼저 보관하고 센서를 새로 시작한다.
3. 센서 수신 후 **수동 조종 켜기**. W/S는 전후진, A/D는 회전이다.
   누르는 동안 이동하며 키를 놓으면 멈춘다. 기본 15cm/s, 조종 범위 3~150cm/s. R 키로 조종을 켜거나 끈다.
   Space/Esc/정지 버튼은 조종을 종료한다. 창 전환·입력 단절도 정지한다.
4. 주변을 천천히 돌아 벽과 통로를 지도에 담는다. 실제 전진과 지도 위치의
   전진 방향이 일치하는지 먼저 확인한다. 조종을 끄고 완전히 멈춘다.
5. 지도 이름을 입력하고 **현재 지도 저장**. Jetson의 `~/d420_maps/`에
   고유한 이름의 YAML/PGM/posegraph/data 파일을 추가한다.
6. 지도에서 빈 공간을 클릭하고 지점 이름과 도착 방향을 입력한 뒤 저장한다.
   방향 0도는 지도 +X, +90도는 +Y이다. 클릭 자체로는 이동하지 않는다.
7. **지점 이동 준비** → 저장 지점 선택 → **경로 확인** → **선택 지점으로 이동**.
   첫 이동은 가까운 빈 공간에서 확인한다. 자율주행 목표 속도는 기본 8cm/s이고 3~150cm/s에서 선택한다. Nav2가
   차체 크기, 관측된 공간과 라이다 장애물을 검사한다.

## 연결과 정지

- ASUS의 K221 연결 프로필에서 WiFi 절전을 해제했다
  (`802-11-wireless.powersave=2`, 연결 재활성화 적용).
- Jetson에서는 사용자가 다음 명령을 실행했고 `Power save: off`를 확인했다.
  `sudo iw dev wlP1p1s0 set power_save off`
  이 명령만으로는 Jetson 재부팅 후 설정 유지가 보장되지 않는다.
- SSH 별칭과 기존 호스트 키는 그대로 사용한다. 연결 복구 후 양쪽 Unix
  시각이 일치하는 것을 확인했다.
- 새 지도 연결은 사람 검출기를 필요로 하지 않는다. 카메라는 Jetson의
  JPEG 릴레이를 통해 표시하며 원본 RGB를 WiFi로 구독하지 않는다.
- 센서 지연, 브라우저 heartbeat 단절, 제어 주기 지연 또는 Nav2 명령 지연이
  발생하면 실제 모터 출력은 0이 된다. 정지 후 자동으로 주행을 재시작하지 않는다.

## 구성과 저장 위치

- `navigation.py`: 지도에 묶인 지점 저장, 차체 전체의 목표 위치 검사,
  Nav2 속도 명령의 유효기간·범위 검사.
- `map_workspace.py`: 지도 저장, 지점 저장, 경로 조회와 이동 API.
- `ros_navigation.py`: Nav2 경로/이동 액션 클라이언트.
- `jetson/navigation/`: `/d420_nav` Nav2 서비스. 출력은
  `/d420/nav_preview_cmd_vel`로 분리한다. 직접 모터 출력 모드는 차단했다.
- 기존 ASUS Lab의 `/d420/manual_cmd_vel` 발행자 하나가 수동·추종·지점 이동을
  공유한다. 다른 조종 작업과 이동을 동시에 시작하지 않는다.
- 지도 연결에서는 `jetson/mapping_bridge.py`가 기존 브리지에 전진 오도메트리
  부호 보정을 적용한다. 과거 전진 시 음수였던 x/vx만 반전하며, 모터 송신
  패킷과 회전·다른 축은 그대로다. 기존 수동/사람 추종 연결은 원래 브리지를 쓴다.
- ASUS 지점 목록: `scenario_lab/runs/navigation/maps.json`.
- Jetson 지도 원본: `/home/seo/d420_maps/`.
- 기존 Jetson 센서 코드는 연결 시 `scenario_lab/backups/jetson_*`로 보관된다.

저장 지도 불러오기와 AMCL 재위치 추정은 이 화면에 아직 구현하지 않았다.
파일은 보관되지만 재부팅 뒤 예전 지점으로 바로 이동하는 기능은 별도 작업이다.

## 앱 안의 실제 RViz

기본 지도 화면은 ASUS에서 실행한 실제 RViz이다. 지도·라이다·로봇 모델을
격리된 가상 X 화면에 렌더링하고 로컬 WebSocket으로 앱에 표시한다.
**RViz 확대·이동**을 누르면 마우스로 RViz를 조작할 수 있다. 수동 조종 중에는
키보드 입력을 주행에 사용하도록 RViz 조작을 잠근다. 지점 저장은 **지점 선택 지도**
탭에서 한다. 카메라는 별도 JPEG 화면이며 RViz가 원본 RGB를 구독하지 않는다.

`hongik-rviz-display.service`가 RViz 화면을 유지한다. 앱을 다시 열면 화면에
재연결하며, 준비되지 않은 경우 `rviz_start.sh`가 시작한다. VNC는 로컬 5908만
사용하고 실제 ASUS 데스크톱을 공유하지 않는다. 브라우저 연결은 로컬 출처와
현재 제어 토큰을 확인한다. 의존 도구는 프로젝트의 `vendor/rviz-runtime`에
배치했다. Ubuntu 패키지를 시스템에 설치하거나 관리자 설정을 바꾸지 않았다.

이번 화면 변경 적용에서는 `/api/navigation/attach`로 기존 매핑 서비스에만
다시 연결했다. 새 지도 작성/오도메트리 리셋은 실행하지 않았다. 이 경로는
실행 중인 `hongik-scenarios`의 `D420_MAPPING_MODE=1`을 확인한 뒤 연결한다.

## 카탈로그 최고속도 선택 적용

2026-11-07 수동 및 지점 이동 목표 속도를 3~150cm/s까지 선택하도록 변경했다.
출처는 보관된 CODBOT 제품표의 D420 항목(1.5m/s, 조절 가능)이며
`docs/d420_catalog_speed.md`에 발췌본을 보관했다. 구매 리비전·적재 상태에 따른
실제 달성 속도는 별도이며 실차 최고속도를 자동 시험하지 않았다.

매핑 브리지에만 `--max-linear-speed 1.5`를 명시한다. 기존 브리지의 기본값은
0.30m/s이다. 시리얼 패킷 인코더에도 명시적 상한을 넘겨 1.50m/s를 넘는 명령은
거절한다. 수동 입력·서버 설정 검증·피드백 범위를 함께 갱신했다.
자율주행은 이동 시작 전에 `FollowPath.desired_linear_vel`을 설정하고 성공을 확인한다.
Nav2의 고속 코너 명령은 선속도와 각속도를 같은 비율로 줄여 곡률을 유지한다.
지역 비용지도는 8×8m, 전방 장애물 관측은 6m까지 사용한다.

가상 로봇/패킷 검사 163개와 브라우저 검사 통과. 실제 Nav2가 1.5m/s 설정을
수용하는지는 이동 목표 없이 확인하고 0.08m/s로 되돌렸다. 기본 조종 속도는
15cm/s, 자율주행 속도는 8cm/s이다. 기존 가속·입력 단절·센서 지연 정지는 유지한다.

배포 전 `최고속도 설정 전 지도`로 현재 지도를 저장했다.
`jetson/restore_checkpoint.py`는 모터 명령 발행자가 없고 차체가 정지한 상태에서
해당 체크포인트를 START_AT_GIVEN_POSE로 복원하며 지도 범위와 현재 위치를 검증한다.
이번 배포에서 복원을 확인한 뒤 지도 세션 ID를 갱신해 저장 목록을 유지했다.
이 도구는 정지 중 배포용이며, 전원 차단 후 이동한 로봇의 위치를 자동으로 알아내는
범용 재위치 추정 기능은 아니다.

## 수동 조종 가속 응답 수정

2026-11-07 최고속도 상한 확대 후에도 가속 제한이 0.05m/s²여서
1.5m/s 명령까지 30초가 걸리는 문제를 확인했다. 수동 조종의 가속 제한을
0.75m/s²로 바꿨다. 명령 기준 0.3m/s까지 0.4초, 1.5m/s까지 2초이며
키 해제와 입력 단절 정지는 유지한다. 트레이의 명령 예측도 같은 가속도를 사용한다.
가상 검사 165개 통과. 실제 차체의 도달 시간은 현장에서 별도 확인한다.
이 변경은 ASUS 앱만 다시 시작해 적용하며 Jetson SLAM 지도는 유지한다.

## 무선 재연결 후 수동 조종 준비 조건

2026-11-07 SSH 응답이 재개된 뒤 Jetson 업타임 유지, 무선 신호 -46dBm,
절전 off를 확인했다. 원본 RGB는 Jetson 내부 릴레이만 구독했고 측정한 무선
TX는 약 4.24Mbit/s였다. 반복 무응답의 근본 원인은 이 정보만으로 확정하지 않았다.

SLAM의 map→odom 시각이 멈춰 지도 위치 계산이 불가능한 상태도 별도로 확인했다.
수동 조종은 지도 좌표 대신 기존 오도메트리·라이다·카메라 유효성 검사로 준비 여부를
판단하도록 `manual_ready`를 분리했다. 저장 지점 이동과 지도 작업의 유효성 검사는
유지한다. 지도 정지 상태를 해소한 것으로 간주하지 않는다. 수동 조종 중 오도메트리
단절 시 정지하는 API 검사를 포함해 변경을 확인했다.

## 동시 조향과 제자리 회전

2026-11-07 수동 조종의 전후진·회전을 독립 축으로 처리한다. W+A/D는
이동하면서 회전하고 A/D만 누르면 제자리 회전한다. W+A에서 W만 놓으면
회전이 이어지고 A만 놓으면 직진이 이어진다. S+A/D도 조이스틱처럼
선속도와 회전 축을 독립적으로 적용한다.

회전 기본값은 0.80rad/s, 화면 조절 범위는 0.20~1.00rad/s,
각가속도는 2.0rad/s²이다. 매핑 브리지의 기존 0.30rad/s 제한도
명시적으로 `--max-angular-speed 1.0`으로 변경했다. 일반 브리지의 기본값은
유지한다. 고속 동시 입력은 `abs(v)+0.198*abs(w)<=1.5`를 만족하도록
두 축을 같은 비율로 줄인다. 키 해제·통신 단절 정지는 유지한다.

가상 로봇 및 패킷 검사 169개, 실제 Chrome의 가상 로봇 키보드 검사 통과.
Jetson 실행 인자, 앱 회전 기본값 0.80, 조종 준비 상태를 확인했다.
검증 도구로 실제 차체에 이동 명령을 보내지는 않았다. 실제 조이스틱과의
체감 일치 여부는 사용자의 주행 확인이 필요하다.

배포 전 멈춘 SLAM에서 지도 이미지 PGM/YAML은 저장했으나 포즈 그래프
저장 서비스가 응답하지 않았다. 부분 백업은
`runs/navigation/turn_upgrade_archive/`에 설명과 함께 보관했다.
사용자에게 알린 뒤 센서·브리지를 다시 시작했으며 실시간 지도는 새 세션이다.
이전의 완전 저장 지도 `최고속도 설정 전 지도`는 별도로 보존한다.
배포 후 새 지도와 지도 좌표 변환, 수동 조종 준비 상태가 정상임을 확인했다.


## 회전 명령 전체 범위와 수동 조종 일시 정지

2026-11-07 보관된 공유 자료의 `01_4WD_시리얼_통신규약.md`에 각속도
0~540×0.01rad/s가 명시됨을 확인했다. 화면 및 매핑 브리지 명령 상한을
5.40rad/s로 확대했다. 이는 프로토콜의 명령 범위이며 실측 최고 회전 속도가
아니다. 기본값은 1.00rad/s, 각가속도는 4.0rad/s²이다. 키를 누르는 동안
반복 회전하며 회전 횟수 제한은 없다. 두 축 혼합 시 기존 바퀴 속도 경계는 유지한다.

최근 실제 중단 기록 `20261107_153702_real_teleop_346685.json` 및
`20261107_153708_real_teleop_110690.json`에서 최신 오도메트리 부재로
조종이 해제된 것을 확인했다. 수동 조종만 최신 센서 지연 또는 제어 주기
지연 시 0 명령으로 일시 정지하고 소유권을 유지하도록 변경했다. 센서가
복구되어도 이전에 누른 키의 명령은 재실행하지 않는다. 키를 모두 놓는
중립 입력 이후 새 방향 입력이 있어야 움직인다. 입력 지연도 같은 방식으로
정지한다. 브라우저 연결 단절·창 이탈·명시적 정지 및 심각한 센서 이상은
기존 해제 동작을 유지한다. 센서 신선도 기준을 늘리거나 무시하지 않았다.

수동 기록은 최근 12000샘플을 유지하는 방식으로 바꾸어 기록 한도 때문에
조종이 종료되지 않게 했다. 원래의 무선 지연 원인을 해결한 것으로 간주하지 않는다.
가상 로봇·패킷·서버 검사 174개 및 Chrome 키보드 검사 통과. 여러 바퀴
회전, 5.40rad/s 인코딩, 지연 중 0 명령, 복구 뒤 중립 입력 전 재출발 금지를
검사했다. 실제 로봇에 자동 이동 시험 명령은 보내지 않았다.

배포 전 지도 이미지와 포즈 그래프 모두 Jetson에 저장했다:
`/home/seo/d420_maps/before_manual_20261107_154123_148813.{yaml,pgm,posegraph,data}`.
센서 재시작 후 실시간 지도는 새 세션이다. 백업을 현재 좌표계에 자동 연결하지 않았다.
Jetson 실행 인자 `--max-angular-speed 5.4`, 수동 조종 준비 상태 및 앱 슬라이더를 확인했다.


## 지도 작성 중 출발·회전·도착 지점 기록

2026-11-07 사용자 요청으로 새 SLAM 지도를 시작하고 정지한 현재 지도 좌표
(0,0,0)을 출발점으로 기록했다. 새 지도 작성 전 기존 지도는 준비 스크립트가
별도 파일로 백업한다. 이번 앱 기능 배포는 ASUS 서버만 재시작해 새 SLAM을 유지했다.

지도 저장 전에도 현재 위치를 출발점·회전 지점·도착점으로 기록할 수 있다.
회전 지점은 여러 개 기록할 수 있고 각각 현재 지도 좌표 및 방향, 역할을 저장한다.
수동 조종은 켜 둔 채 방향 키를 놓고 차체가 완전히 정지했을 때 기록한다.
활성 자율주행 중 기록, 이동 중 기록, 오래된 센서/지도 좌표 기록은 거절한다.

지점은 `runs/navigation/maps.json`의 현재 SLAM 세션에 연결된 작성 중 지도에
즉시 기록된다. 지도 저장 시 동일 지도 항목에 원격 지도 경로를 연결하여
기록한 지점을 유지한다. 서버 재접속은 같은 세션의 항목을 다시 연결하지만,
새 SLAM 세션으로 기존 지점을 자동 복사하지 않는다. 지도 클릭 지점도 완성 전
기록할 수 있으며 기존 차체 크기·빈 공간 검사를 유지한다. 현재 차체 위치를
기록하는 작업은 관측이 아직 덜 된 출발점도 허용하며 이동 목표로 사용할 때
지도의 빈 공간 검사를 다시 적용한다.

실제 지도 파일 저장 전에는 Nav2 준비·이동이 차단된다. 역할 표시와 기록은
모터 명령을 발생시키지 않으며 여러 지점의 자동 순회 경로 실행 기능은 별도다.
가상 검사 176개와 Chrome 출발점·수동 조종 중 회전 지점 버튼 검사 통과.


## 전방 깊이 기반 상대 L자 경로 실험

2026-11-07 저장 지도 원점에서 재위치 추정(약 4cm, 3° 차이)을 확인한 뒤,
Nav2 경로 중심선은 생성됐으나 출발 직후 두 자세에서 차체 외곽이 lethal 셀과
겹쳐 IsPathValid가 false임을 확인했다. 자동 이동 목표는 보내지 않았다.
사용자가 지도·라이다 장애물 판정을 쓰지 않고 직진→오른쪽90°→직진을
요청하여 별도 `DepthRoute`와 앱 03 패널을 추가했다.

실제 거리는 사용자가 첫 구간 3m 조금 넘게, 둘째 구간 2m 조금 넘게라고
알려 주었다. 화면 초기값은 임시 3.2m / 2.2m이며 직접 수정 가능하다.
시작 클릭 당시의 오도메트리 위치·방향을 기준으로 한다. 저장 지도와
저장 지점 좌표를 사용하지 않는다. 기본 8cm/s, 최대 12cm/s, 제자리 회전
최대 0.20rad/s이다. 90° 우회전 후 둘째 구간을 시작하고 도착 시 0 명령으로
종료한다. 거리·회전 정확도는 아직 실제 주행으로 검증하지 않았다.

Jetson의 `hongik-depth-observer.service`는 D435 정렬 깊이를 보정 정보와
TF로 base_footprint에 투영하고 5cm~1m 높이의 전방 장애물 점을 생성한다.
YOLO나 모터 발행자는 만들지 않는다. 실제 첫 확인에서 유효 깊이 비율
약 77~82%, 장애물 620점, 전방 폭 ±30cm 안 최근접 X 약 0.78m를 확인했다.
`깊이 관측 연결` 버튼은 이 관측 서비스만 실행하며 센서·지도는 재시작하지 않는다.

직선 구간은 관측된 점과 1초 예측 차체 외곽을 검사해 감속·정지 또는 작은
방향 보정을 선택한다. 경로에서 25cm를 벗어나면 중지하고, 장시간 진행 없음도
중지한다. 넓은 우회나 전역 재계획은 지원하지 않는다. 전방 카메라에는 측후방
사각이 있으므로 관측 점이 없다는 이유로 회전 공간 전체가 검증된 것은 아니다.
UI에 이 한계를 표시했다. 현재 조종 기능과 구분하여 라이다 스캔/지도 장애물
검사는 사용하지 않지만 오도메트리 신선도·명령 발행자 단일성·브라우저 연결·
제어 주기·트레이 상태 검사는 유지한다. 깊이 관측 지연 0.35초 초과 시 중지한다.

가상 로봇 검사 187개 및 Chrome의 새 경로 버튼 시작/Escape 정지 검사 통과.
3.2m 전진→우90°→2.2m 전진→정지를 가상 운동으로 검증했다. 실제 차체에
이동 명령은 보내지 않았으며, 사용자의 버튼 입력으로만 시험을 시작한다.
기존 지도/세 지점 백업은 유지하고 기존 isolated Nav2 서비스는 중지했다.

## 2026-11-09 깊이 단절 시 경로 복구

상세 기록: `../diagnostics/depth_recovery_20261109/README.md`.
350ms 관측 지연을 즉시 세션 종료하던 동작을 정지 대기로 변경했다.

다리 앞이었고 전방 깊이 유효 영역 부족도 관찰되어 출발 공간 확인이 필요하다.

## 2026-11-09 Jetson 내부 경로 제어 검증 단계

사용자의 명시 승인으로 경로 엔진을 Jetson 단일 USB 소유 브리지 안으로 옮겼다.
ASUS는 시작·정지 요청과 표시만 담당하며, Wi-Fi 상태 지연만으로 로컬 경로를
중지하지 않는다. 수동 조종의 명령 시간 제한은 유지한다. 정지 요청은 응답까지
재전송하며 통신 단절 시 앱 정지 전달도 지연될 수 있다.

현재 앱의 `Jetson 직진 검증 · 60cm / 10초` 버튼은 전체 L자 경로 대신
첫 직선만 최대 0.12m/s, 보고 거리 0.60m 또는 10초로 제한한다.
로컬 센서 단절·유효하지 않은 값은 정지 조건이다. 상세 배포, 백업, 테스트와
실제 주행 검증의 한계는 `diagnostics/local_route_proposal_20261109/README.md` 참조.
첫 시험은 USB 송신·보고 이동이 있었으나 사용자가 실제 바퀴 미동작을 확인했다.
이후 수동 12/15cm/s는 실제 동작 확인. 아직 전체 L자 실주행 성공 상태가 아니다.

이후 앱 검증 버튼으로 약0.60m 보고 거리에서 종료하는 실제 전진을 사용자가
확인했다. 그 뒤 요청에 따라 전체 L자 모드와 짧은 검증 모드를 분리했다.
전체 모드는 12cm/s 상한으로 입력 거리·우회전90도·두 번째 직선을 실행한다.
전체 첫 시험은 첫 직선 종료 뒤 약40도 우회전 보고 상태에서 깊이 영상
가림/유효 영역 부족으로 정지했다. 두 번째 직선과 도착은 아직 검증되지 않았다.
