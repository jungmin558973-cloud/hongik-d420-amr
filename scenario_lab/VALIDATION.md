# 주행·트레이 제어 앱 검증

## 2026-10-25 텔레옵·트레이 모드 추가

- 모의 제어·센서·시리얼·HTTP API 검사와 실제 Chrome 키보드/포인터 검사를 실행했다. 최신 집계와 해시는 `docs/operator_validation.json`을 확인한다.
- W/S 전후진, A/D/방향키 회전, 키 해제 정지, 화면 버튼, 속도 변경, 입력란 타이핑 제외, Space 정지, 창 포커스 이탈 정지를 확인했다.
- 트레이 OFF/LEVEL/PREDICTIVE와 기존 급정지·회전·언덕 세 시나리오의 미리보기를 완료했다. `qa/operator_modes/browser_report.json`, 최종 갱신 확인은 `browser_smoke.json`에 있다. 모두 실차 미연결 상태다.
- 기존 ESP32 원본을 보존했다. 새 앱용 펌웨어는 실제 ESP32-S3 보드 설정으로 컴파일했으며 `firmware/build_manifest.json`에 소스/바이너리 해시를 기록했다. 업로드하지 않았다.
- 예측은 명령/입력 코스 모델이다. RealSense 깊이 분석, 실제 미래 액체 상태, 미래 키 입력을 사용하지 않는다. 물 유출·실제 서보 축 각도도 측정하지 않는다.
- 실차 USB·IMU·서보·주행 통합은 장치를 연결한 후 검증해야 한다. 펌웨어의 USB 설정과 센서 종류는 `firmware/README.md`를 확인한다.

## 실시간 표시 경로 검사

별도 8768 포트의 합성 센서 fixture를 썼다. ROS/SSH를 생성하지 않고 제어 명령 0건으로:

- JPEG 픽셀이 카메라 패널에 표시됨.
- 지도 PNG가 3D 바닥 텍스처와 2D 지도 패널에 표시됨.
- 제어 엔진은 idle인 상태에서 센서 위치 입력만 바꿨을 때 모델 위치도 움직임.
- JavaScript 오류 0건.

`qa/synthetic_media_report.json`·`synthetic_media.png`는 이 **합성 데이터 검사**의 결과다.
첨부 영상을 실제 카메라 영상으로 대체하지 않는다.

## 언덕 치수

각도 15°, 폭 60cm, 길이 80cm를 반영했다. 길이 기준의 3가지 선택을 단위 테스트했다.
사용자가 **한쪽 경사판 표면 길이 80cm**로 확인해 기본값을 `slope_surface`로 변경했다.
높이 약 20.7cm, 한쪽 수평 길이 약 77.3cm이며 대칭 삼각형의 전체 수평 길이는 약 154.5cm다.
변경 후 기존 제어/형상 테스트와 실제 서버 응답·HTML 기본 선택값을 다시 확인했다.

## 실차 범위

사용자는 현재 밖에 있고 Jetson을 가지고 있지 않다고 확인했다. 따라서 실차 연결 준비·영상 수신·
모터 주행은 실행하지 않았다. 기본 주소는 오늘 K221에서 실제 확인했던 `seo@192.168.0.47`이다.
외부 Wi-Fi에서 그 내부 IP의 연결 성공을 주장하지 않는다.

실제 제동 거리, 90° 오차, 언덕 진입·경사 정지 유지, 카메라 지연/프레임율, 실제 SLAM 정합은
K221에서 장치를 연결한 뒤 확인해야 한다. 실제 높이/기울기 IMU와 트레이 제어·물 유출 측정은 미연결이다.
