# L자 시험 + 중간 급정지 · 2026-11-16

## 시험 순서

기본 첫 직선 3.2m → 오른쪽 90° 회전 → 두 번째 직선 2.2m. 각 거리는 UI에서 변경 가능.
전체 경로의 급정지 체크가 켜져 있으면 첫 직선의 절반(기본 1.6m)에서 한 번 급정지한다.
급정지 때 정상 가속 램프를 우회하여 선속도·각속도 0을 즉시 명령하고, 피드백으로 정지를 확인한다.
0 속도 명령은 기계식 비상 브레이크가 아니며 실제 제동거리·바퀴 미끄러짐은 보장하지 않는다.

- 기본 속도 12cm/s, L자 경로 설정 범위 3~20cm/s. 기존 수동 조종·Nav2 설정은 변경하지 않는다.
- 중간 급정지 후 |선속도| < 1.5cm/s 및 |각속도| < 0.04rad/s를 1초 연속 확인한 후 재출발한다.
- 재출발 시 직선 구간 원점을 바꾸지 않는다. 제동 중 이동도 기존 직선 거리와 누적 기록에 포함한다.
- 회전 전 같은 정지 기준을 0.4초 연속 확인한다. 그다음 오른쪽 90°를 오도메트리 yaw로 제어한다.
- 도착 시에도 0.4초 연속 정지 확인 후에만 완료 표시한다. 정지 확인이 8초 안에 끝나지 않으면 종료한다.
- 급정지는 한 번만 수행한다. 깊이 관측 복구나 단계 재진입으로 다시 발동하지 않는다.
- 짧은 60cm/10초 검증은 기존 한계를 유지하고 중간 급정지 추가는 적용하지 않는다.

## 기존 정지 조건

깊이 유효 영역 검사, 0.35초 관측 만료, 정상 관측 3장·150ms 이상·차체 정지에 따른 복구, 3초 복구 한계,
장애물 대기·진행 없음·경로 이탈·피드백 오류·명시적 정지는 유지한다. 검사나 watchdog을 꺼서 완주시키지 않는다.
회전 시 전방 카메라만으로 측후방 공간이 검증되지 않는 한계도 동일하다. 넓은 장애물 우회·전역 재계획은 지원하지 않는다.

L자 경로는 저장 지도/Nav2를 사용하지 않는 상대 오도메트리 경로다. 지도를 다시 만들거나 지점을 삭제하지 않는다.
센서 복구가 안 되는 상황에서 무조건 완주시키는 기능이 아니며, 기존 깊이 단절의 물리 원인이 해결됐다는 뜻도 아니다.

총 실행 제한은 기존 고정 240초 대신 거리·속도에 맞춰 max(240초, 예정 직선시간*3+60초)를 적용한다.
저속·긴 경로가 단순히 240초를 넘는다는 이유로 끝나는 문제를 줄인다. 장애물 대기·진행 없음 제한은 그대로다.

## 표시와 기록

UI에 현재 단계, 중단·대기 이유, 깊이 영상 지연, 급정지 완료 여부를 표시한다.
상태/실험 요약에 events, brake_at_m, brake_trigger_distance, brake_end_distance, brake_done을 포함한다.
원격 앱이 수신한 실험 기록은 기존 runs 경로를 사용한다. 기록된 거리·속도는 오도메트리이며 외부 실측은 아니다.

## 검증 범위

`python3 -m unittest discover -s tests -v`: 11개 통과. 전체 L자, 회전된 초기 방향, 한 번의 급정지,
관성 있는 모의 차체의 제동거리, 도착 정지 확인, 짧은 관측 단절 복구, 주기적 관측 단절을 포함한 완주,
장시간 단절 종료, 명시적 정지, 장애물 대기 종료, 정지 실패 종료, 오도메트리 오류,
입력 검증, Jetson 호스트의 제어 지연·피드백 단절·짧은 검증 제한을 확인했다.
수정 Python 파일과 JavaScript 문법도 검사했다. 실제 Edge 브라우저의 로컬 HTTP fixture에서 기본 속도 12cm/s, 급정지 체크 ON, 급정지 OFF 및 짧은 검증 요청 전달을 확인했다(1개 통과). ROS나 모터에는 연결하지 않았다. 화면은 L_TEST_UI.png에 보관한다.

실제 Jetson/센서/모터에 적용하거나 이동 명령을 보내지 않았다. 192.168.0.47:22 연결이 불가능했다.
물리 응답, 제동 거리, 깊이 영상 지연/유효 영역 부족 원인, 실제 회전 오차는 현장 시험이 필요하다.
기존 앱의 과거 검증 문서는 이전 버전의 기록이며 이번 수정의 실물 검증 근거가 아니다.
