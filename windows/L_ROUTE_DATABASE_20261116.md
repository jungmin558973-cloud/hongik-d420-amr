## 직진 후 정지 문제

실제 시험 로그는 현재 Jetson 연결 불가로 읽지 못했다. 따라서 방금 실험의 정지 원인을 확정하지 않았다.
이전 코드에서 재현한 문제는 첫 직선 끝에 가까워질수록 속도를 0.025m/s까지 줄이는 점이다. 실제 모터가 0.04m/s 미만 명령에 반응하지 않는 모형에서는 0.7m 직선의 0.621m 지점에서 멈추고 35초 후 진행 없음으로 종료됐다. 이는 시험용 가정이며 실물 모터의 측정된 임계값은 아니다.

수정 내용:

- 주행·트레이 제어실 탭의 숨김/닫기 이벤트가 다른 화면에서 시작한 L자에도 정지 요청을 보내던 코드를 수정했다. 두 주행 화면 모두 Jetson L자 실행 중에는 창 전환·닫기만으로 취소하지 않는다. 이 경로가 실제 시험에서 작동했는지도 당시 로그 없이는 확정할 수 없다.

- 끝부분 속도 하한을 0.06m/s로 높였다. 사용자가 지정한 속도 상한은 넘지 않는다. 위치 허용 오차 3cm 안에서 정지한다. 실제 정지 거리는 바퀴·하중에 따라 달라진다.
- 회전 명령은 최소 0.10rad/s, 최대 0.20rad/s로 만들고 0.6rad/s² 변화율 제한을 적용했다. 허용 오차 약 2.3° 안에 들어오면 0 명령을 보내 회전이 가라앉은 뒤 두 번째 직선으로 진행한다.
- 회전 중 실제 yaw 오차 감소로 진행 여부를 갱신한다.
- 종료 시 이전 주행 단계, 남은 거리/회전 오차, 마지막 명령과 자세, 정지 문구를 저장한다.
- `L자 전체 실험 시작`과 `직진만 검증 · 60cm / 10초 · 회전 안 함`을 명확히 구분했다.
- 웹 서버와 Jetson 경로 프로세스의 배포 버전이 다르면 시작하지 않는다.

깊이·장애물·오도메트리·트레이 연동 오류 정지는 유지한다. 카메라의 측후방 사각과 실제 전원/통신 문제를 해결했다고 간주하지 않는다. 급정지는 첫 직선 절반에서 0 명령을 보내는 기능이다.

## 실험 버튼을 누르면 저장되는 자료

Jetson `/home/seo/d420_ws/scenario_lab/runs/experiments.sqlite3`에 실험별로 누적 저장한다. SQLite는 Python 기본 기능이므로 별도 DB 서버 설치는 필요 없다.

| 실험 | 고유 ID, 시작/종료 시각, 배포 버전, 설정, 완료/중단 상태와 사유 |

| 종료 분석 | 중간 급정지/회전/두 번째 직선 진입 이벤트, 정지 당시 단계·오차·센서 상태 |

`experiments`와 `samples` 두 테이블을 사용한다. 주요 수치는 직접 CSV 열로 제공하고 기타 진단값은 각 샘플의 `data_json`에 보존한다. 시나리오·수동·사람 추종·지점 이동도 웹 제어 루프에서 자동 기록한다. 미리보기 자료는 `mode=preview` 및 `simulated=true`로 구분한다. 실차 `mode=real`과 섞어 실측으로 해석하지 않는다.

L자 기록은 Jetson 차체 제어 프로세스가 직접 20Hz 제어 스냅샷을 저장하므로 Windows 화면/연결 단절에도 계속된다. DB 쓰기는 별도 스레드에서 배치 처리하며, 저장 큐를 기다리느라 모터 제어를 블로킹하지 않는다. DB 준비가 안 되면 L자를 시작하지 않고, 저장 오류를 감지하면 주행을 중단한다. 요청 재전송은 같은 실험을 중복 생성하지 않는다.

시작을 확인받은 L자는 후속 시작 명령이나 브라우저 heartbeat가 필요 없다. 웹 앱 서버가 종료/재시작돼도 이미 수락된 경로를 취소하지 않는다. Jetson 경로/모터 프로세스와 센서는 계속 동작해야 한다. 현장 센서·모터 USB·트레이 안전 상태 실패는 여전히 정지 조건이다. STOP/Space/Esc 및 Windows 연결 창의 명시적 접속 종료는 정지 요청을 보낸다.

주행 중단 시 두 주행 화면 위에 큰 정지 사유·발생 단계 안내를 표시한다. 예정된 중간 급정지와 센서 복구 일시 정지는 노란색 안내로 구분한다. 사용자가 확인해 닫기 전까지 표시한다. 화면 연결 중에는 갱신된 정지 사유를 바로 보며, 연결이 끊긴 동안에는 현장 상태를 즉시 표시할 수 없다.

제어 스냅샷 20Hz는 센서 실측 20Hz를 뜻하지 않는다. 현재 ESP32 펌웨어의 상태 보고는 통상 약 2Hz이며, 원래 측정값이 바뀌지 않은 반복 행에는 `tray_new_sample=false`를 기록한다. 고속 트레이 출렁임 분석에 필요한 ESP32 고주기 원시 계측은 이번 배포에서 추가하지 않았다. PWM은 명령이며 서보 내부 엔코더 실측이 아니다. 실제 차체 USB 전송 완료 확인값은 없으므로 `motor_tx_confirmed=null`이다.

보통 0.25초 단위 및 종료 시 디스크에 반영한다. 강제 전원 차단 시 아직 반영되지 않은 마지막 자료가 사라질 수 있다. 다음 동일 기록 프로세스 시작 때 종료 확인 없는 실험을 `interrupted`로 표시한다. DB는 자동 삭제하지 않는다. 실행 중 원본 SQLite를 보관하려면 `-wal` 파일을 빼고 단독 복사하지 말고 SQLite backup 기능을 쓰거나 제어 서비스를 정상 종료한 뒤 복사한다.

## 확인과 다운로드

1. 주행·트레이 제어실 상단의 `05 실험 기록` 또는 L자 패널의 `실험 기록 보기`를 누른다.
2. 시작 시각·실험 종류·결과·정지 사유·샘플 수를 확인한다.
3. 원하는 실험의 CSV 또는 JSON을 내려받는다. 실행 중 다운로드는 그때 디스크에 반영된 자료까지 포함한다.

최근 100개를 화면에 표시한다. 이전 기록은 DB에 계속 남는다. CSV에는 주요 신호와 전체 샘플 JSON 열이 있고, JSON에는 설정·결과·모든 샘플이 있다. 화면이 끊겼을 때는 현장 정지 수단을 사용할 수 있어야 한다.

## 적용 순서

1. 로봇을 완전히 정지하고 Windows 연결 창을 닫는다.
2. **07 ZIP을 새 폴더에 전체 압축 해제**한다. 예전 06 ZIP을 다시 설치하지 않는다.
3. `Setup-Jetson.cmd` 실행으로 Jetson 앱을 업데이트한다. 이 작업은 기존 runs DB를 삭제하지 않는다.
4. `Install-HongikCafe.cmd` 실행으로 Windows 바로가기를 갱신한다.
5. HONGIK CAFE를 열고 ESP32 연결을 다시 시작한다. 서보·영점·방향·수평 유지를 확인한다.
6. 지도·지점 이동 → 03 수평 유지 + L자 시험 → 깊이 관측 연결.
7. 우선 짧은 직진 검증 후, 실제 거리와 우회전 공간을 확인하고 **L자 전체 실험 시작**을 누른다. 기본 속도 12cm/s, 거리 3.2m/2.2m, 첫 직선 중간 급정지 선택 기본 켜짐.
8. 정지하면 실험 기록에서 해당 행의 사유와 CSV/JSON을 확인한다.

ESP32 펌웨어는 이번에 변경하거나 자동 업로드하지 않았다. 이전 수평/예측 기능과 보드별 준비 조건은 CURRENT_STATUS_20261116.md를 따른다. 기본은 수평 유지, 선행 예측 보정은 선택이다.
